# Release notes

What each release changed, and for whom. Three audiences, because a single
list serves none of them:

- **For operators** — you run an instance: installing, upgrading, backups,
  secrets, the doctor, what a page means at 3am.
- **For admins** — you configure this instance in the Helm: agents, users and
  roles, channels, plugins, flags.
- **For agent authors** — you write manifests, skills and plugins against the
  engine.

A change that is genuinely invisible to all three is recorded in the release
commit and does not appear here.

!!! note "About the first block below"

    This page began with the release that introduced it, and its first version
    block carries entries backfilled from the handful of releases immediately
    before — the work was already shipped; only the note for it is new. Later
    blocks describe exactly the release they name. Delete this note once that
    first block is a few releases old.

This page is written by the release. The developer record — one line per
conventional commit, generated by semantic-release — is `CHANGELOG.md` in the
repository, and it is not going away; it answers a different question.
Contributors: `changelog.d/README.md` is how a pull request adds to this page.

## 1.122.0 — 2026-10-31

### For operators

A container deployment can now point the dashboard's Logs page at its real logs: set `GENUS_LOGS_URL`, or the Helm value `logs.url`, to where this deployment's logs are viewed, and the page offers an **Open logs** link to it. The chart renders the variable on the bridge only when the value is set. The URL is shown to every operator, so keep it credential-free. See [Deployment](deployment.md#the-helms-observe-pages). ([#792](https://github.com/Ironsail-llc/genus-os/pull/792))

A dashboard running more than one replica no longer signs operators out when two replicas refresh the same session at once: a refresh token spent less than 30 seconds earlier and presented again now returns the same new pair instead of a 401. Signed-out and revoked tokens get no such window, and no session affinity is needed. Upgrading applies migration 161, which adds two columns and an index to `user_sessions`. See [Identity, roles and tenants](enterprise/02-identity.md#sessions-and-refresh). ([#794](https://github.com/Ironsail-llc/genus-os/pull/794))

The Python image ships pyasn1 0.6.5, which closes four parser advisories reported against 0.6.4 this week. Nothing changes in how an instance is configured or run. Upgrade on the usual path; see [Deployment](deployment.md) for the release flow. ([#795](https://github.com/Ironsail-llc/genus-os/pull/795))

### For admins

Observe › Logs no longer looks broken on a deployment without journald. It says the deployment writes its logs to standard output and that they are read with your cluster's log tool, and it shows an **Open logs** link when one is configured. Auto-refresh is hidden in that state, and **Refresh** asks again whether journald is available instead of showing a red error. See [Deployment](deployment.md#the-helms-observe-pages). ([#792](https://github.com/Ironsail-llc/genus-os/pull/792))

You can now correct a memory fact the pipeline got wrong. On Observe › Memory,
**Edit** beside a fact changes its text, its entities or both, and asks for a
reason. The original is kept in the fact's history first, and the fact shows
**Operator-confirmed** afterwards; a new text refreshes the fact's search
vector when the bridge can reach the embedding provider, and otherwise the card
says the search index is pending. See [Operating the instance](enterprise/07-operate.md)
for what an edit does and does not change.

([#793](https://github.com/Ironsail-llc/genus-os/pull/793))

Settings › Flags now recovers from a session that lapsed mid-visit: it retries once, and if the session has really ended it shows **Sign in** instead of a red error beside controls it cannot apply, and a failed reload clears the flags rather than leaving stale ones on screen. Every flag change now needs a reason of 1 to 500 characters at the Bridge as well as in the page, and appears in the audit log as `control.set` with who made it, the value and the reason. See [Operate](enterprise/07-operate.md#flags-and-the-observe-to-enforce-ladder). ([#794](https://github.com/Ironsail-llc/genus-os/pull/794))

Observe › Runs is now a page you can work from: a summary of runs, failures, deliveries and cost over the period you choose, filters for status, agent, trigger and period, and a full-width table with Load more. A run that chose not to send (silent, suppressed, no output, published) reads "no delivery expected" in a neutral tone, and only a send that failed is red. Selecting a run opens a drawer that explains it: what it was asked, which models it tried, tokens and cost, and each step with its tool input and output, timing and errors. See [Observability](OBSERVABILITY.md) for the delivery categories and the 30-day step retention. ([#796](https://github.com/Ironsail-llc/genus-os/pull/796))

**Settings › Config** opens much faster: the instance reads its config file once per page load rather than once for every setting. The sections appear as soon as the page knows which settings exist, and each section's values fill in a moment later. The list of settings is downloaded again only when it has changed ([Configuration](configuration.md#from-the-helm-without-a-shell)).

([#797](https://github.com/Ironsail-llc/genus-os/pull/797))

## 1.121.0 — 2026-10-31

### For operators

An agent's tool success rate now counts every tool call that returned an error, including errors reported as an object rather than text. `log_interaction` reaches the bridge at `BRIDGE_URL` instead of the engine's own loopback, and a bridge refusal now says why (for example `agent not authorized` for an agent missing from `agent_capabilities.json`). `store_memory` and `record_resolution` refuse calls missing their required arguments, naming what was missing, instead of storing an empty fact. See [Tools](TOOLS.md). ([#789](https://github.com/Ironsail-llc/genus-os/pull/789))

### For admins

A workflow run now records what each tool step was given and what it returned,
each capped at 64 KB with a visible truncation marker, and owners and admins can
read a run step by step through a new run-detail endpoint that is never cached.
See [Observability](OBSERVABILITY.md#workflow-runs-step-by-step) for the routes. ([#788](https://github.com/Ironsail-llc/genus-os/pull/788))

In Automations, a workflow that has run now expands to list its recent runs
with their status, start time, duration and steps ok/failed. Opening a run
shows each step's tool, error, and recorded input and output as collapsible
JSON, so a failed run can be read without shell access. See
[Observability](OBSERVABILITY.md#workflow-runs-step-by-step) for what is recorded. ([#790](https://github.com/Ironsail-llc/genus-os/pull/790))

### For agent authors

A job a plugin schedules through `genus.jobs` is now recorded as a run, the
way a workflow is: each execution leaves a row with its status, duration, the
value the job returned (capped) and, on failure, the error. The job appears in
the dashboard's workflow list as `plugin:<name>`. See [Plugins](PLUGINS.md)
for where to read its runs and what to return. ([#791](https://github.com/Ironsail-llc/genus-os/pull/791))

## 1.120.0 — 2026-10-30

### For operators

The visual canvas now draws with a model you choose: **Canvas model** on the Providers page, saved by the same **Save default**, and left at "Same as the fleet default" it runs on whatever your fleet runs on. Model ids are dialled exactly as written, so the canvas works on any provider you hold a key for, not only OpenRouter ([Model providers](deployment.md#model-providers)); a `DASHBOARD_MODEL` value without a provider prefix is no longer read as an OpenRouter model. When generation fails, the canvas says why and its Retry asks for a new page, a page restored from an earlier session can be regenerated, and a failed update in the background shows its reason with a Retry instead of disappearing into the browser console. ([#779](https://github.com/Ironsail-llc/genus-os/pull/779))

### For admins

The chat panel docked beside a Helm view now has a collapse button in its own header, a slim tab at the right edge brings it back, and the Helm remembers per browser whether you left it open ([Web chat (the Helm)](channels/webchat.md#the-docked-chat-panel)). The Tasks board and the counters above the Tasks and Agents views pick their columns from the space they actually have beside the sidebar and the chat panel (four, two or one), so cards no longer shrink to slivers or push the page sideways. The chat home opens on a landing before the first message, with a greeting, the Dashboard's figures, its quick actions and the suggested prompts, and gives way to the conversation, centred at a readable width, as soon as a message arrives. Agent replies in the dashboard chat render as readable Markdown that follows the light or dark theme, and dashboard chat turns ask the agent to answer first and keep replies short ([Configuration](configuration.md#how-replies-look-in-the-chat-panel)). ([#779](https://github.com/Ironsail-llc/genus-os/pull/779))

## 1.119.0 — 2026-10-30

### For admins

An owner or admin of any tenant can now decide that tenant's approvals in the Inbox, not only the platform tenant's operators. The Inbox also lists proposed actions waiting on review, such as drafted outreach, as Proposal cards with Approve and Reject. Each decision is recorded with the deciding operator and the tenant, and members and viewers still cannot decide. See [Native sales intelligence](SALES_INTELLIGENCE.md). ([#751](https://github.com/Ironsail-llc/genus-os/pull/751))

### For agent authors

A plugin's own rule can now decide the plugin's proposals. `Operations.decide` accepts `policy:<plugin>:<version>` for actions proposed with `proposed_by="<plugin>"`, and the audit trail records which version of the rule acted. Every approval publishes `operation_action.approved` on the `operations` stream, so a workflow your plugin ships can execute the action as soon as it is approved. New store methods (`list_actions`, `claim_action_by_id`, `cancel_action`, and a full-row `get_action`) mean a plugin never has to query the ledger tables itself. See [Plugins](PLUGINS.md#proposing-an-external-effect) and [Operations ledger](OPERATIONS.md). ([#751](https://github.com/Ironsail-llc/genus-os/pull/751))

## 1.118.0 — 2026-10-30

### For operators

Slack and plugin-channel conversations now remember their exchanges, across
engine restarts, the way the Helm's chat does; Slack's `/clear` now empties
both the live and the stored history, so a cleared conversation stays cleared
after a restart. A new setting, `ROBOTHOR_CHANNEL_MAX_CONCURRENT_RUNS`
(default 8), caps how many channel runs are in flight at once, and messages
over it wait their turn rather than being refused. See
[Configuration](configuration.md).

A plugin channel's senders, such as a storefront, an SMS provider or a support
form, no longer get the engine's `401 authentication required` on a deployment
that requires authentication: a `POST` to a mounted channel's own path reaches
the channel, which checks its own signature or token, and other requests there
still need the engine token.

([#754](https://github.com/Ironsail-llc/genus-os/pull/754))

The Automations view in the Helm now has an External: n8n section that shows
each workflow in your n8n instance with its failures over the last 24 hours and
7 days, when it last failed, and a link that opens it in n8n. Its header badge
turns amber when a workflow has failed recently and grey when the monitor has
not polled successfully, and it is a single muted line while n8n monitoring is
switched off. See [n8n monitoring](integrations/n8n.md). ([#755](https://github.com/Ironsail-llc/genus-os/pull/755))

The Plugins page now shows, on each plugin's card, the agents it installed (with their schedules) and the workflows it shipped (with their triggers), and says "none" when it ships neither. The Workflows list under Automations now includes workflows defined in `docs/workflows/` that have never run, each labelled with where it came from: the plugin that shipped it, or `workspace`. See [Plugins](PLUGINS.md#seeing-what-a-plugin-shipped). ([#759](https://github.com/Ironsail-llc/genus-os/pull/759))

Genus OS can now watch an external n8n instance: set `ROBOTHOR_N8N_BASE_URL`, store an n8n API key in the vault and turn on `ROBOTHOR_N8N_ENABLED`. The engine then polls the workflows and failed executions, tells the main agent once about each failure, and raises one warning if n8n stays unreachable for three polls. It is off by default, and the `n8n.*` doctor checks report whether it is set up and keeping up. See [n8n monitoring](integrations/n8n.md). ([#760](https://github.com/Ironsail-llc/genus-os/pull/760))

On Kubernetes the bridge now reaches the engine (the chart sets
`ROBOTHOR_ENGINE_URL` on the bridge and opens the network policy both ways), so
Settings › Providers lists providers, models and the fleet default again, and
when the engine is unreachable the page names what to check instead of
"engine unavailable". The bridge's `/ready` stays at 200 but adds
`degraded: true` and an `engine` field when the engine cannot be reached, and
the doctor lists a `bridge.engine` row with the address it tried. Save default
and the setup wizard's default-model step now work with the bridge and the
engine in separate containers, because the engine writes `_defaults.yaml` in
its own manifest directory and reloads it before answering. The dashboard's
live event views work on Kubernetes too, because the chart gives the dashboard
the in-chart cache's host, port and password key, lets it through the policy
and restarts it on rotation, which ends the once-a-second cache error in its
logs; see [Configuration](reference/configuration.md),
[Deployment](deployment.md) and [Event bus](event-bus.md). ([#772](https://github.com/Ironsail-llc/genus-os/pull/772))

### For admins

Webhook channels can now verify senders that sign `"<timestamp>.<body>"` with
HMAC-SHA256 and send the hex digest in one header and the timestamp in another:
set `signature_scheme: hmac_ts_hex` and name the timestamp header with the new
`timestamp_header` field (default `X-Webhook-Timestamp`). The timestamp is unix
seconds and must fall within the channel's `timestamp_tolerance_seconds`. See
[Event Bus](event-bus.md#webhook-ingress) for the fields and the refusal reasons that are logged. ([#762](https://github.com/Ironsail-llc/genus-os/pull/762))

When the Channels page cannot list the channels, it now says why (the bridge
could not reach the engine, the engine refused the request, a version mismatch,
or the status the engine answered) and keeps the cards from the last good read,
marked as possibly out of date. When the Plugins page cannot read the plugin
set, it says which hop failed, the bridge-to-engine link or the
dashboard-to-bridge link, and a refresh that fails after a good read keeps the
last listing on screen, marked as unconfirmed, with its switches locked. See
[Channel access](channels/access.md) and [Plugins](PLUGINS.md). ([#772](https://github.com/Ironsail-llc/genus-os/pull/772))

### For agent authors

Several plugins can now extend the same agent. A patch's `append:` adds single
items to a list — a hook identified by its stream and event type, or a value in
`bootstrap_files`, `tools_opt_in` and similar (never creating a tool allowlist an agent
does not have) — and `detach:` (or removing the
plugin) takes back only those items, so two plugins no longer collide over
`hooks`; plugins can also ship their own `docs/webhooks.d/<name>.yaml` channels
and `brain/agents/<agent>.d/` instruction fragments. A plugin that uses any of
this declares plugin contract `2.0`, which this engine accepts alongside `1.0`
and older engines refuse. See [Plugins](PLUGINS.md#composable-patches-append-and-detach). ([#752](https://github.com/Ironsail-llc/genus-os/pull/752))

Agents can now start and report on workflows from a chat: `list_workflows`
shows each workflow's triggers, last run and recent failures, `run_workflow`
starts one with an optional payload (seen by its steps as `event.payload`) under
the workflow's own service identity, as a cron or hook run gets, and can wait
up to two minutes for the result, and `workflow_runs` lists recent runs with
each step's status. `run_workflow` is opt-in and denied to the `user`
and `member` roles by default; new instances get it on main from the template,
and an existing instance must add `run_workflow` to the main manifest's
`tools_opt_in` list. See [Tools](TOOLS.md) for when to use `run_workflow`
instead of `spawn_agent`. A workflow can also raise its tool-call rate limit
(the fleet default of 30 a minute) with a top-level `rate_limit_per_minute`,
and a step the limit blocks now waits for it instead of failing the run, so
a burst of events slows down rather than losing runs. ([#753](https://github.com/Ironsail-llc/genus-os/pull/753))

A plugin channel can now serve many conversations at once: messages in one
conversation run in order, different conversations run side by side, and every
successful exchange is remembered in the conversation's history, across
restarts. `handle_message` takes `record_turn` and `history_limit` to opt out of
that memory or bound it, and `ROBOTHOR_CHANNEL_MAX_CONCURRENT_RUNS` (default 8)
caps the runs all channels have in flight, queueing rather than refusing. See
[Plugins](PLUGINS.md) and [Configuration](configuration.md).

The engine no longer asks for its own token on a `POST` to a mounted channel's
path, so every `POST` route in a channel's `inbound_router` must authenticate
the request itself and refuse it with its own `401` or `403`.

([#754](https://github.com/Ironsail-llc/genus-os/pull/754))

Agents and plugins can now keep curated reference documents in named
knowledge-base collections (`<plugin>/<topic>`) and search one collection with
`kb_search`, which fuses semantic and keyword matches the way memory search
does. `kb_upsert_document` skips a document that has not changed and
re-indexes one that has; `kb_delete_document` and `kb_list_collections` round
out the set. See [Knowledge Base](knowledge-base.md). ([#756](https://github.com/Ironsail-llc/genus-os/pull/756))

Plugins can now keep their own data without shipping a migration:
`PluginState` stores JSON objects by kind and key for each plugin and tenant,
with optional expiry. Plugin tools can also read the fleet's model chain
instead of pinning a model, and check phone numbers against the
do-not-contact list before texting or calling. See
[Plugins](PLUGINS.md#state-and-shared-primitives). ([#757](https://github.com/Ironsail-llc/genus-os/pull/757))

Code that sends through the email channel can now pass an HTML body and a per-send SMTP from-address. `html=` sends a plain-text and HTML alternative in one message on every transport, and `sender=` replaces the instance's from-address on SMTP (the Google and Microsoft 365 transports send as their signed-in account and ignore it). The do-not-contact check still runs first on every send. See [Email](channels/email.md#html-and-sender). ([#758](https://github.com/Ironsail-llc/genus-os/pull/758))

A new read-only tool, `plugins_overview`, lists every installed plugin with what it contributes: tools with their descriptions, doctor checks, agents with their schedules, workflows with their triggers, patched agents and other files. Use it for "what does this plugin give us?" instead of reading the asset ledger by hand. See [Tools](TOOLS.md#what-plugins-contribute-plugins_overview). ([#759](https://github.com/Ironsail-llc/genus-os/pull/759))

Two read-only tools answer questions about the operator's n8n automations: `n8n_list_workflows` lists them with failure counts, the last error and links, and `n8n_recent_failures` lists failed executions in a time window. Both read the n8n monitor's snapshot, never call n8n, and return `not_configured` while the monitor is off. Failures reach the main agent as `workflow_failure` notifications with `source: n8n`. See [Tools](TOOLS.md#n8n-automations-n8n_). ([#760](https://github.com/Ironsail-llc/genus-os/pull/760))

## 1.117.0 — 2026-10-29

### For operators

A tool call whose outcome was never confirmed no longer blocks that tool for good: shell commands, code runs, the browser and file writes are not held back at all (a possible duplicate is the accepted trade-off), and a reworded retry of an outside-world write such as a send waits for the earlier call for 24 hours at most. After that, housekeeping releases the call and chat labels it as released automatically, not as an operator's decision. The assistant can also open files attached to email, from Gmail or Microsoft 365 alike: `gws_gmail_get_attachment` downloads one (up to 20 MB) into `<workspace>/inbox/email/` with the same quarantine and retention as Telegram attachments and reads PDF, Word, Excel, PowerPoint and text. See [Durable engine execution](features/runtime-recovery.md#how-long-an-unknown-outcome-blocks-a-tool) and [Tools](TOOLS.md). ([#741](https://github.com/Ironsail-llc/genus-os/pull/741))

### For admins

The owner's assistant can now read the instance env file, with secret values masked to their last four characters and free-text comments hidden; every other caller, including sub-agents, is still refused. Two new owner-only tools, `config_get` and `config_set`, read and change settings the same way `genus config` does. See [Tools](TOOLS.md). ([#741](https://github.com/Ironsail-llc/genus-os/pull/741))

### For agent authors

`read_file` and Telegram attachments now return the text of PDF, Word, Excel and PowerPoint files, stopping at the 50,000-character cap, and any other binary file comes back as a size and type summary. Agents can also write to Jira with `jira_create_issue`, `jira_add_comment`, `jira_transition_issue` and `jira_update_issue`. The Jira writes are opt-in, so name them in `tools_allowed` or `tools_opt_in`, and they are denied to the `user` and `member` roles. See [Tools](TOOLS.md) for what each format yields and the Jira key formats. ([#741](https://github.com/Ironsail-llc/genus-os/pull/741))

## 1.116.1 — 2026-10-28

### For operators

`GENUS_INVITE_GRANT_TTL_SECONDS` sets how long the one-shot SSO binding grant armed with an invite lives. The default is seven days, up from one hour; lower it if you hand invites over in person. The grant is still spent by a single verified sign-in for exactly the invited address. See [Configuration](reference/configuration.md). ([#740](https://github.com/Ironsail-llc/genus-os/pull/740))

### For admins

Inviting someone from Settings › Users & roles now defaults to sign-in through your identity provider when the instance has one, and the copied instructions send the invitee to the dashboard to choose "Sign in with SSO". Before this, an unticked invite made an account that could never sign in, and the instructions pointed at the provider's address, which shows a page of metadata. An SSO invite now stays valid for seven days instead of one hour, and a failed sign-in says the account may not be set up for SSO yet and to ask your administrator. See [Configuration](configuration.md) for how invites and grants work. ([#740](https://github.com/Ironsail-llc/genus-os/pull/740))

## 1.113.0 — 2026-10-28

### For operators

The image now ships LiteLLM 1.100.4 instead of 1.92.2. 1.92.2 is affected by
CVE-2026-114612, and nothing changes in how agents call models. LiteLLM now
installs boto3 as one of its own dependencies, which makes the image slightly
larger. Upgrade as usual: see
[Backup, restore and upgrade](enterprise/06-backup-upgrade.md#upgrading). ([#718](https://github.com/Ironsail-llc/genus-os/pull/718))

`genus agent search`, `genus agent install <slug>` and `genus agent publish` now reach the marketplace at programmaticresources.io; the previous default pointed at a parked domain, so hub installs could not succeed. The dashboard's Marketplace links now open there too. Set `PROGRAMMATIC_RESOURCES_URL` (CLI) or `dashboard.env.NEXT_PUBLIC_PROGRAMMATIC_RESOURCES_URL` (Helm) to use a different marketplace host. See [Quickstart](quickstart.md) for the install flow. ([#726](https://github.com/Ironsail-llc/genus-os/pull/726))

### For admins

Installing a plugin from a local wheel no longer fails on macOS with "The
wheel member … escapes its root." The default macOS temp directory runs
through a symlink, which the extractor mistook for an escape. Building a
plugin index and the managed-fleet plugin check are fixed the same way. See
[Plugins](PLUGINS.md). ([#714](https://github.com/Ironsail-llc/genus-os/pull/714))

`genus plugin sync` now installs the agents and workflows a plugin declares,
which makes `pip install --target` into the plugin directory followed by a
sync a complete install. `genus plugin remove` deletes a plugin from the plugin
directory without `--force` and retires its agents the way the Helm retires
one. A plugin that has disappeared is reported by sync, never retired
automatically. `genus plugin sync --strict` exits `3` when a plugin's files
were refused, for a deploy job that needs to notice. See
[Plugins](PLUGINS.md#install-sync-and-remove).

If you develop a plugin as an editable install (`pip install -e`), its
`genus-plugin.yaml` is now found, so its recorded manifest digest changes: the
plugin reports drift and does not load until you run `genus plugin sync` once.

([#726](https://github.com/Ironsail-llc/genus-os/pull/726))

### For agent authors

A plugin can now ship agents, workflows, edits to an existing agent and other
workspace files: declare them under `agents`, `workflows`, `patches` and
`files` in `genus-plugin.yaml`. `genus plugin install` and `genus plugin sync`
render and copy them, keeping the operator's agent overrides across upgrades,
and `genus plugin remove` retires them. See
[Plugins](PLUGINS.md#shipping-agents-workflows-and-workspace-files).

`genus plugin new <name>` scaffolds a plugin repository that builds a correct
wheel as-is: an example tool and its schema, an agent template, the
`genus-plugin.yaml` declaring both, contract tests, and a CI workflow that
builds the wheel and prints its sha256. See
[Plugins](PLUGINS.md#starting-a-plugin).

([#726](https://github.com/Ironsail-llc/genus-os/pull/726))

## 1.112.0 — 2026-10-27

### For operators
