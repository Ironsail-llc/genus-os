# Release notes

What each release changed, and for whom. Three audiences, because a single
list serves none of them:

- **For operators** — you run an instance: installing, upgrading, backups,
  secrets, the doctor, what a page means at 3am.
- **For admins** — you configure this instance in the Helm: agents, users and
  roles, channels, plugins, flags.
- **For agent authors** — you write manifests, skills and plugins against the
  engine.

A change that is genuinely invisible to all three is recorded in the release
commit and does not appear here.

!!! note "About the first block below"

    This page began with the release that introduced it, and its first version
    block carries entries backfilled from the handful of releases immediately
    before — the work was already shipped; only the note for it is new. Later
    blocks describe exactly the release they name. Delete this note once that
    first block is a few releases old.

This page is written by the release. The developer record — one line per
conventional commit, generated by semantic-release — is `CHANGELOG.md` in the
repository, and it is not going away; it answers a different question.
Contributors: `changelog.d/README.md` is how a pull request adds to this page.

## 1.104.0 — 2026-10-07

### For operators

Requested external-verification status checks now recover after a service restart without another click. Bounded retries and exclusive leases keep recovery read-only, preserve uncertain spending reservations, and prevent an old worker from overwriting a newer check. A missing confirmation or exhausted retry budget returns the task to waiting for the person; recovery never repeats a form or payment submission. See [Autonomous execution](AUTONOMOUS_EXECUTION.md) for recovery and verification requirements. ([#619](https://github.com/Ironsail-llc/genus-os/pull/619))

Payment status now distinguishes a partial authorization release from a refund, including when only part of the authorized amount was charged. Released and remaining authorization appear separately, and delayed evidence can reconcile without changing your spending allowance. See [Autonomous execution](AUTONOMOUS_EXECUTION.md) for payment evidence and remaining issuer-integration requirements. ([#620](https://github.com/Ironsail-llc/genus-os/pull/620))

External-verification handoffs can now recognize affirmative completion messages without asking the agent to guess future page wording. Known exact confirmation criteria remain supported, while new whole-page guesses are rejected and uncertain outcomes stay pending. See [Autonomous execution](AUTONOMOUS_EXECUTION.md) for supported confirmation rules and read-only recovery. ([#621](https://github.com/Ironsail-llc/genus-os/pull/621))

Desktop and browser helpers no longer inherit the engine's whole environment. Tools like `scrot`, `xdotool` and any application the desktop tools launch now start from the same filtered environment `exec` already uses, so the fleet's decrypted credentials are not handed to every child process. `ROBOTHOR_EXEC_ENV_MODE` still defaults to `observe`, which changes nothing today and only logs, per agent, the names `enforce` would withhold — so this is a one-line flag change away from taking effect rather than a second code change. See [Configuration](configuration.md) for the exec environment modes. ([#623](https://github.com/Ironsail-llc/genus-os/pull/623))

Personal automation is off unless you turn it on, and turning it off now stops a task being finished as well as being started — reconciling a result, arming a verification check and recovering one after a restart all re-read your switch and your grant first. A verification that lapses no longer leaves its budget stuck: the task moves to "waiting for you" and you can clear it. **Erase submission record** removes the page text a browser observed on your behalf — your name, date of birth, address and the answers you gave — keeping only that a record was taken, when, and under which grant; records also expire on their own after a year. See [Configuration](configuration.md) for the switch and the retention setting. ([#626](https://github.com/Ironsail-llc/genus-os/pull/626))

Personal automation is now absent, not merely idle, on an instance that has not set `ROBOTHOR_AUTONOMY_ENABLED=true`: every `/api/autonomy/*` route answers 404 to a caller of any role, including the endpoints that store a payment card and set spending authority. The accidental-paste masking that rewrites card-shaped numbers in chat now applies only to messages a person typed, so a webhook body or a federated message carrying a tracking number or an IMEI reaches your agent unaltered. See [Autonomous execution](AUTONOMOUS_EXECUTION.md) for the switch. ([#627](https://github.com/Ironsail-llc/genus-os/pull/627))

Interrupted engine runs now retain action evidence, cancellation requests, and provider spending limits across recovery. Saved plans execute once, and chat recovery distinguishes verified results from unresolved actions. Apply the additive database migrations before restarting; see [Durable engine execution](features/runtime-recovery.md) for recovery and rollback guidance. ([#628](https://github.com/Ironsail-llc/genus-os/pull/628))

Browser profiles are keyed per agent again. A regression in the personal-automation
release keyed each Chromium profile by run, so every run began from a fresh profile:
cookies never survived between runs, and the workspace accumulated one profile
directory per run. Profiles now persist per agent, as described in
[Personal autonomous execution](AUTONOMOUS_EXECUTION.md). ([#629](https://github.com/Ironsail-llc/genus-os/pull/629))

On Telegram and in the Helm web chat, a message you send while the agent is still working now joins that task instead of waiting behind it. The agent picks it up at its next safe point: Telegram confirms with a 👀 reaction, and the Helm marks the message "Added to the running task". If the agent was already writing its answer, you get that answer and then a revised one that takes your addition into account. See [Telegram channel](channels/telegram.md#adding-context-while-the-agent-is-working) and [Web chat](channels/webchat.md#adding-context-while-the-agent-is-working). ([#631](https://github.com/Ironsail-llc/genus-os/pull/631))

Coding jobs are refused until you set `ROBOTHOR_CODING_REPO_ROOTS` to the directories repositories may live under (the live workspace and the service user's home are refused even under a root), and every job's shell runs in Claude Code's sandbox, which needs `bwrap` able to create unprivileged user namespaces plus `socat` — `genus doctor` fails `claude_code.ready` without them. Jobs use the engine user's own Claude Code login (the new `zz-claude-code.conf` engine drop-in, installed by `scripts/install-units.sh`, makes `~/.claude` and `~/.claude.json` writable so it can refresh), or a token stored by `genus claude-code login`, and `genus claude-code status` proves either with a one-turn call. Apply migration 144 (`coding_jobs`) before restarting the engine: interrupted jobs resume on the next start, and finished jobs' worktrees, config directories and `genus/cc-*` branches are removed after `ROBOTHOR_CODING_RETENTION_DAYS` (default 7). See [Tools](TOOLS.md) for where worktrees live and what a job may read. ([#637](https://github.com/Ironsail-llc/genus-os/pull/637))

Your instance can now review pull requests on its own: install the `pr-reviewer` agent and the two `pr-review` workflow templates, set `ROBOTHOR_PR_REVIEW_REPOS`, and apply migrations 145–147. A review with a blocker or major finding, or an earlier one not reported resolved, is never posted as an approval, and each review is posted exactly once. To match a review bot your team already runs, point `ROBOTHOR_PR_REVIEW_GUIDELINES_PATH` at your team's guidelines and list `owner/repo:PREFIX` entries so reviews check the linked Jira ticket's acceptance criteria; you can also ask the assistant to review one pull request. Never run it on the same repositories as another review bot — see [PR reviewer](PR_REVIEWER.md) for setup, cutover and parity. ([#638](https://github.com/Ironsail-llc/genus-os/pull/638))

The pull-request reviewer and Claude Code coding jobs now work as advertised on a live instance: a deferred agent such as `main` gets the full wait it asked for through `tool_call`, a timed-out wait no longer blocks later calls, and the reviewer has its own small toolset. Run `scripts/install-units.sh` so the engine unit lets Claude Code's Bash sandbox mount `/proc` (`genus doctor` checks this) and the restart lock opens under `fs.protected_regular=2`. Reviews now pick up only requests made to the bot itself (not its teams), resume after an interrupted run, never run on a closed pull request, and stop for one pull request when you call `pr_review_intake(pr=..., action="skip")` — see [the PR reviewer guide](PR_REVIEWER.md). ([#639](https://github.com/Ironsail-llc/genus-os/pull/639))

Pull-request reviews now read what a human reviewer reads: the PR description (runbooks and commands in it included), earlier comments, whether the branch conflicts with its base, and the checks on the head commit — a conflict or a failing check blocks the review. Pull requests from `ROBOTHOR_PR_REVIEW_DEEP_LINES` changed lines (1,500) get a deeper effort, explicit lens passes and a completeness pass, and anything that can pay twice, lose data, leak across tenants or break the base is graded at least major. Reviews run on `opus`, the alias for the newest Opus, and every review footer names the model and effort that wrote it. See [PR reviewer](PR_REVIEWER.md). ([#640](https://github.com/Ironsail-llc/genus-os/pull/640))

A PR review whose post to GitHub fails no longer pays for a second review: GitHub's transient 500/502/503/504 errors and dropped connections are retried twice within the post, and if posting still fails, the automatic retry re-posts the review that was already written instead of starting a new Claude Code job. The Chat failure message now says which attempt failed and that a retry is automatic. See [PR reviewer](PR_REVIEWER.md). ([#641](https://github.com/Ironsail-llc/genus-os/pull/641))

Owner commands run through `robothor-host-exec` can write under `/home` again (`ProtectHome=no`). That unit only, and the engine stays confined, so CLIs no longer fail with "Read-only file system" after they have done their work. `genus config get` now names the systemd drop-in or environment file that sets a value for each unit. `genus config set NAME VALUE --apply` changes it there: it writes a `zz-genus-config-*` drop-in, names any later drop-in that would keep winning (`--override` outranks it), reloads systemd and schedules the restart 15 seconds out. Reinstall the host-exec unit on upgrade. See [Configuration](configuration.md#when-a-systemd-unit-sets-it). ([#643](https://github.com/Ironsail-llc/genus-os/pull/643))

The destructive-command guardrail no longer blocks harmless commands that merely mention SQL words (for example an echo of "delete from"); SQL patterns now apply only when a SQL client is in the command. The guardrail reminder now tells the agent to fix blockers on its host and tell the operator, instead of not working around them. See [Security](security.md). ([#644](https://github.com/Ironsail-llc/genus-os/pull/644))

Helm chat's Canvas now follows the conversation: when the agent draws a chart or breakdown, the canvas opens as the main view with chat docked beside it, including for replies that run longer than two minutes (previously cut off and recovered without their visual) and for views that contain links. Concurrent requests also share one session refresh, so operator views (Goals, Memory, Settings and the rest) no longer drop out of the sidebar when a session renews. See [Web chat (the Helm)](channels/webchat.md). ([#648](https://github.com/Ironsail-llc/genus-os/pull/648))

### For agent authors

Telegram stopped losing album members: one picture that failed to download used to end the batch silently, and each member now reports its own failure while the rest still arrive. `/secure` no longer answers a sender this instance has never heard of, or recites the dashboard path into a group chat, and nothing from a stranger's message is quoted back to you. Contract documents are read only from the websites a grant lists, its payment-provider frames, or the site the task is on, and an oversized one is refused before it is downloaded. See [Configuration](configuration.md). ([#626](https://github.com/Ironsail-llc/genus-os/pull/626))

Agents can now read a pull request's diff, its changed files and a two-commit comparison with `github_pr_diff`, `github_pr_files` and `github_compare`. A manifest that lists them in `tools_allowed` can also post reviews and act on review threads. `github_create_review` keeps findings that point outside the diff in the review body, so they are never dropped. ## 1.103.0 — 2026-09-21

### For operators

Genus can now run a native sales pipeline — discovery, research, qualification,
contact review, drafting, approval and delivery — with every integration switch
off until you turn it on, and with no message leaving the instance without your
exact-message approval. An instance that never selects a sales release runs

The Helm gains a sales pilot: integration setup that never takes a secret,
bounded research requests, a prospect and contact review console, measured
weekly reports, and a two-step deployment that binds the fleet to one reviewed,
verified release. Role permissions tighten with it — migration 138 denies
`web_render` and the `sales_*` tools to the `service`, `user` and `member`
defaults, so a sales agent now needs its own role rather than inheriting the
catch-all allow, and `admin` and `owner` are unchanged. See
[Native sales intelligence](SALES_INTELLIGENCE.md) and
[Agents](enterprise/04-agents.md). ([#624](https://github.com/Ironsail-llc/genus-os/pull/624))

### For agent authors

Manifests gain four delegation and routing keys — `v2.spawn_allowed_agents`,
`v2.max_spawn_total`, `model.response_format` and `model.provider_order` — and

## 1.101.0 — 2026-09-20

### For agent authors

A `curl` your snippet spawns is now evidence like any other request: `execute_code`
records what its child processes did, so a `subprocess.run(["curl", "-X", "POST", …])`
appears in `http_calls` with `via: "curl"` and is held to the same unread-response rule
as `urllib`. Children the recorder cannot see through are named under
`egress_unobserved` rather than passing silently. And if the snippet fails *after* a
write took effect, the response bodies it consumed but never printed come back under
`lost_responses` — read them before re-sending, because a re-send is a duplicate. See
[Tools](TOOLS.md). ([#602](https://github.com/Ironsail-llc/genus-os/pull/602))

## 1.100.2 — 2026-09-18

### For agent authors

A triage report's executive summary no longer counts against the items it
mentions. "**2 Critical** issues … **2 High** … **3 Low** items" is a tally of
categories, not a verdict on anything, and a summary bullet that then names
one item no longer files that item under every severity the summary counted —
before this, an item filed exactly once under Critical was reported as "under
three verdicts" and, at `enforce`, your agent was re-asked to fix a report that
was already right. Section headings (`## Critical Issues (3)`) and labels
(`**Severity: High**`) work exactly as before. See
[Agents](enterprise/04-agents.md). ([#601](https://github.com/Ironsail-llc/genus-os/pull/601))

## 1.100.1 — 2026-09-18

### For operators

An engine restart no longer pages you for stopping: since the previous release
the engine's own health server re-raised the one SIGTERM systemd had sent, the
engine read that as a second signal and exited 1, and every deploy looked like
a failure to `OnFailure=`. A repeat of the stop signal inside two seconds of
the first is now recognised as the same stop and ignored, and the health
server no longer touches the process's signal handlers. A deliberate second
`kill` later in a hung drain still ends the engine at once but exits 0 — a stop
you asked for is not a crash — while a drain that outlives `TimeoutStopSec` is
still killed by systemd and still pages. See
[Backup, restore and upgrade](enterprise/06-backup-upgrade.md) for the upgrade
path this makes quiet again. ([#600](https://github.com/Ironsail-llc/genus-os/pull/600))

## 1.100.0 — 2026-09-18

### For agent authors

`execute_code` now holds the HTTP your snippet makes on its own — through
`urllib`, `requests` or `http.client` — to the same rule as a `genus_tools`
call: a POST, PUT, PATCH or DELETE whose response body your snippet never
printed is counted in `unread_responses`, named as `POST http://host/path` in
`unread_response_tools`, and listed with its status under `http_calls`. A
rejected write (4xx/5xx) and a reply with nothing substantial in it are never
counted. The act→observe reminder now arrives as its own `[SYSTEM]` message,

You can now switch a plugin off without uninstalling it, and find out which of your plugins stopped loading and why. The verbs are `genus plugin list`, `info`, `enable`, `disable`, `sync` and `doctor`, and a plugin whose files have changed since you recorded it is held back until you look, rather than loaded quietly. A damaged record never stops the instance booting — but nothing is governing while it is damaged, and the doctor and the Helm both say that plainly instead of implying otherwise. See [Plugins](PLUGINS.md). ([#566](https://github.com/Ironsail-llc/genus-os/pull/566))

Observe › Memory, Audit and Logs are screens now rather than placeholders. You can search what this instance believes and retire a fact with a reason, read the guardrail change log, export audit events as CSV with whatever filters you are looking at, and tail a unit's journal. An auditor sees Audit and neither of the other two. See [Deployment](deployment.md) for what each page answers, and for what a forget deliberately does not do. ([#567](https://github.com/Ironsail-llc/genus-os/pull/567))

You can now install a plugin from a signed registry instead of running pip by hand. The index is Ed25519-signed over canonical JSON, the wheel is checked against its sha256 before anything opens it, and an offline scan produces a verdict that gates the install — safe installs, review needs your explicit acceptance, blocked never installs. See [Plugins](PLUGINS.md) for the verdicts and for pinning a publisher's key. ([#569](https://github.com/Ironsail-llc/genus-os/pull/569))

Installing Genus OS is one line: `curl -fsSL https://ironsail-llc.github.io/genus-os/install.sh | bash -s -- --substrate compose`. Every download is pinned to a release tag, the compose files are validated before anything starts, and a piped run without `--yes` is a preview that writes nothing. The Helm chart is published to an OCI registry at each release, so a cluster install no longer needs a clone of the repository. See [Quick Start](quickstart.md). ([#570](https://github.com/Ironsail-llc/genus-os/pull/570))

Hand your assistant a credential over a channel and it can now keep it: the vault is the store for application credentials, so a value the assistant is given is stored, proved against the vendor, and answered for with a fingerprint rather than the secret. `genus secrets status` prints where each credential lives and which store wins, and `genus secrets migrate --from-env` moves the ones still in your secrets file — it refuses bootstrap names, says up front how many vault rows it will not touch, and never replaces a fresher row with a stale environment copy. After the upgrade, restart every Genus process so they all read the same precedence, and delete the migrated entries from the secrets file, because `genus doctor` now reports a dead environment value that was shadowing a live vault row. Your assistant's manifest also needs `v2.credentials: operator` before the vault write tools will answer it; see [Secrets](enterprise/05-secrets.md). ([#576](https://github.com/Ironsail-llc/genus-os/pull/576))

### For admins

Settings › Plugins now lists every distribution the engine loaded, with its version, state, groups and contributions. On a fresh install the first affordance is Record installed plugins, which writes the lockfile; after that an enabled switch and a Reload engine plugins bar apply a change without a restart. A damaged lockfile says plainly that nothing governs instead of implying that something does. See [Plugins](PLUGINS.md) for the same operations from a shell. ([#568](https://github.com/Ironsail-llc/genus-os/pull/568))

The Helm's Plugins page can install from a registry: a name, an optional version, an index picker, and a Preview that shows the artifact, its sha256, the publisher key id and the verdict before anything is installed. Install is enabled only for a safe verdict, or for review once you accept that exact plan, and never for blocked. Remove is offered on the cards the registry installed. See [Plugins](PLUGINS.md). ([#572](https://github.com/Ironsail-llc/genus-os/pull/572))

Microsoft Teams is a channel now, and it ships as the `genus-teams` plugin rather than as part of the core. It delivers over the Bot Framework, asks a question as an Adaptive Card, and validates every inbound request's token before it does anything with it. The channel stays inert until `ROBOTHOR_CHANNELS` names it. See [Teams channel](channels/teams.md) for the Azure app registration and the ingress decision. ([#573](https://github.com/Ironsail-llc/genus-os/pull/573))

### For agent authors

A run now gets pace-aware deadline notes at 50, 80 and 95 per cent of its ceiling, a repeat-call guard that answers an identical read of an unchanged file short, and exec timeouts bounded by the time actually left. All of it sits behind one flag, `ROBOTHOR_STEP_EFFICIENCY_MODE` — off, observe or enforce, observe by default — so it can be watched before it is enforced. See [Configuration](configuration.md) for how to set it. ([#571](https://github.com/Ironsail-llc/genus-os/pull/571))

You can hand an agent to another instance: `genus agent export` writes a bundle with the manifest, the instructions, the referenced skills and a `requires` list, and `genus agent install` takes a path, a directory or a URL with a checksum. A credential literal anywhere in an export is a hard failure, and adapter values are collapsed to environment names before they are written. The Helm offers the same export as a Share button. See [Agents](enterprise/04-agents.md) for the bundle format and what `requires` checks. ([#574](https://github.com/Ironsail-llc/genus-os/pull/574))

An agent that reads the same unchanged file twice now gets a short answer the second time instead of the whole file again. That was the intent before, but the guard resent the file whenever its earlier copy had fallen out of the model's context — which is most of a long run — so an agent could spend a large part of its budget re-reading its own work. A file that really changed is still re-read, so nothing is ever hidden from the model. See [Configuration](configuration.md) for the flag that governs it. ([#575](https://github.com/Ironsail-llc/genus-os/pull/575))

An agent now sees only the credentials its manifest grants it. Name them under `secrets:` and the environment of every process the agent execs is scrubbed to that grant plus a short allowlist, with `ROBOTHOR_EXEC_ENV_MODE` as the ladder from `off` through `observe` to `enforce`; a sub-agent inherits nothing, since its grants are read from its own manifest. `vault_get` no longer hands a value to the model — it answers with a one-way fingerprint, and the new `vault_test` dials the vendor's identity endpoint so an agent can prove a credential works and say who it authenticates as without ever reading it. Read a credential through `robothor.secrets` rather than the process environment, and see [Configuration](configuration.md) for the grant syntax, the ladder and what the scrub leaves behind. ([#576](https://github.com/Ironsail-llc/genus-os/pull/576))
