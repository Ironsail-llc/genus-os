# Release notes

What each release changed, and for whom. Three audiences, because a single
list serves none of them:

- **For operators** — you run an instance: installing, upgrading, backups,
  secrets, the doctor, what a page means at 3am.
- **For admins** — you configure this instance in the Helm: agents, users and
  roles, channels, plugins, flags.
- **For agent authors** — you write manifests, skills and plugins against the
  engine.

A change that is genuinely invisible to all three is recorded in the release
commit and does not appear here.

!!! note "About the first block below"

    This page began with the release that introduced it, and its first version
    block carries entries backfilled from the handful of releases immediately
    before — the work was already shipped; only the note for it is new. Later
    blocks describe exactly the release they name. Delete this note once that
    first block is a few releases old.

This page is written by the release. The developer record — one line per
conventional commit, generated by semantic-release — is `CHANGELOG.md` in the
repository, and it is not going away; it answers a different question.
Contributors: `changelog.d/README.md` is how a pull request adds to this page.

## 1.99.0 — 2026-09-17

### For operators

A run now ends itself when its wall-clock budget runs out, instead of being
killed mid-call by whatever was counting down outside it. At 90% of the budget
it switches to writing — the agent keeps only the tools that produce and check
its output, and is told how many seconds are left; at 100% no further model
call is issued, any call in flight is cancelled after a short grace, and the
run finishes with an honest summary of what is and is not on disk.
`ROBOTHOR_RUN_BUDGET_SECONDS`, `ROBOTHOR_RUN_WRAPUP_FRACTION` and
`ROBOTHOR_RUN_BUDGET_GRACE_SECONDS` control it, and all three are listed in
[Configuration](configuration.md) along with the
`ROBOTHOR_STEP_EFFICIENCY_MODE` rung that has to be at `enforce` for any of it
to act. ([#587](https://github.com/Ironsail-llc/genus-os/pull/587))

### For agent authors

The repeat guard now catches a loop that varies its arguments, not only one
that repeats a call exactly: calls are grouped by a coarse signature — the
command head for `exec`, the path for a read, the domain for a fetch, the query
stem for a search — and only escalate while their results keep returning what
the run already has, so genuinely new work is never touched. The progress
check-in also becomes directive past halfway through the budget, naming the
output path and asking for it before any further exploration, once two
check-ins have found nothing written. Both ladders sit behind
`ROBOTHOR_STEP_EFFICIENCY_MODE=enforce`; see [Configuration](configuration.md)
for that rung and [Tools](TOOLS.md) for what each guarded tool does. ([#587](https://github.com/Ironsail-llc/genus-os/pull/587))

## 1.98.0 — 2026-09-17

### For operators

The WildClawBench image now provides the environment those tasks assume — an
`eval` Python environment at the exact path two Code Intelligence tasks name,
plus ffmpeg, poppler and a documented `conda` shim — so a task's warm-up no
longer fails on a missing binary and skips the task with a zero. Rebuild the
bench tools image before your next sweep. See
[Benchmark sandbox](runbooks/BENCHMARK_SANDBOX.md) for how benchmark runs are
kept away from your production tenant. ([#584](https://github.com/Ironsail-llc/genus-os/pull/584))

A command's output is no longer silently cut short. `exec` still shows the
first ~4,000 characters, but the whole stream is now written to a file under
`.robothor/exec/` in the agent's workspace whose path comes back in
`stdout_path`, and the marker in the visible part names it — so nothing an
agent asked for is destroyed, and a run can go and read the rest. Three new
ladder settings ship on `observe`, where they log what `enforce` would do and
change nothing an agent sees: `ROBOTHOR_TRUNCATION_LEDGER_MODE` (a run is told,
once, about output it never read back), `ROBOTHOR_ACT_OBSERVE_MODE` (a run that
changed something and never looked again is told so) and
`ROBOTHOR_VERDICT_COMMITMENT_MODE` (a triage deliverable should carry one
verdict per item). All three appear in the
[Configuration reference](reference/configuration.md) and on the Controls page,
and each writes an `agent_guardrail_events` row on `observe` so the evidence
exists before the rung moves. `ROBOTHOR_EXEC_SPILL_MAX_BYTES` (default 8 MiB)
caps one spill file, and a spill that would leave under 64 MiB free is skipped. ([#585](https://github.com/Ironsail-llc/genus-os/pull/585))

Agents sorting or labelling a folder of images now see *why* the vision model
answered as it did, and behavioural rule 18 tells them a filename is a claim
about a picture rather than evidence of it. This closes a measured failure where
an agent got 93% of a hundred-image sort right, distrusted its own answers
because the filenames disagreed, and shipped the filenames instead. Rows from a
backend that gives no reason say `reason_missing: true` rather than having one
invented — on a weak local vision model that can be most of them — and no
setting changes. See [Tools](TOOLS.md). ([#586](https://github.com/Ironsail-llc/genus-os/pull/586))

### For agent authors

Your agent can now recover output the engine had to cut. An `exec` result over
the window carries `stdout_truncated`, `stdout_chars` and `stdout_path`, and
`read_file` on that path returns the whole stream — so a listing whose tail used
to vanish is something the agent can page back, and that read is exempt from the
repeat guard. Prefer `genus_tools` inside `execute_code` over `curl` or `urllib`
when calling an API: a proxied call keeps its full response on the run's ledger
whatever the snippet prints, and `execute_code` now reports how many responses
the snippet never showed itself. Both contracts, and the rule that a
state-changing call invalidates what you observed before it, are in
[Tools](TOOLS.md). ([#585](https://github.com/Ironsail-llc/genus-os/pull/585))

`analyze_image` now takes an optional `choices` list of 2–20 labels, and every
answered row comes back with a short `reason` saying what the model saw. With
`choices` a row carries a validated `choice` spelled the way you spelled it —
matching is equality on a case- and punctuation-normalised form, never a prefix
or a fuzzy match — and a reply naming none of them is asked once more and then
reported as that row's error. A spilled batch also returns a `sample` holding
one row per distinct answer, asking for `scan.png` when the file is `scan.jpg`
now reads the file instead of failing, and `resolved_from` means "the path you
asked for" in both vision tools. See [Tools](TOOLS.md). ([#586](https://github.com/Ironsail-llc/genus-os/pull/586))

## 1.97.0 — 2026-09-17

### For operators

`ROBOTHOR_PARALLEL_TOOL_CALLS` (default 4) decides how many of one turn's tool
calls run at once; only calls the platform has classified read-only are ever
grouped, and 1 restores the previous strictly sequential behaviour. The new
`execute_code` tool lets a granted agent run Python that calls its own tools,
bounded by `ROBOTHOR_EXECUTE_CODE_MAX_CALLS`, `ROBOTHOR_EXECUTE_CODE_TIMEOUT`,
`ROBOTHOR_EXECUTE_CODE_MAX_OUTPUT` and `ROBOTHOR_EXECUTE_CODE_MAX_APPROVALS`; it
requires `exec`, refuses a container-sandboxed agent, and always runs with the
scrubbed child environment whatever `ROBOTHOR_EXEC_ENV_MODE` is set to. All five
settings are listed in the
[Configuration reference](reference/configuration.md). **Run `genus migrate`
before restarting the engine on this release**: a new migration adds
`agent_run_steps.batch_id` / `batch_position`, and until it is applied the step
writer records the older shape and says so once at ERROR. ([#583](https://github.com/Ironsail-llc/genus-os/pull/583))

### For agent authors

Your agent can now do several things in one turn. Independent read-only tool
calls on the same turn run at the same time, and a new `execute_code` tool runs
a Python snippet that calls your agent's own tools through `genus_tools`, so a
loop over fifty items costs one turn instead of fifty. Grant `execute_code`
alongside `exec` in `tools_allowed`, and write "for each…" work as a snippet
rather than a call per item. Both are documented in [Tools](TOOLS.md), with the
exact rule for which calls may run together and what a snippet may reach. ([#583](https://github.com/Ironsail-llc/genus-os/pull/583))

## 1.96.0 — 2026-09-17

### For operators

`ROBOTHOR_DELIVERABLE_CONTRACT_MODE` changes what `enforce` does: it used to
record a verdict, and it now re-asks the agent once with the report and then
fails a run whose deliverable is the wrong shape rather than letting it report
`completed`. The default is unchanged (`observe`, and the master switch off),
and a new migration adds `agent_runs.task_text` — the originating prompt,
redacted and capped — because the check had no source of task text before it.
Both settings are listed in the
[Configuration reference](reference/configuration.md); read the
deliverable-contract runbook in the repository before promoting the rung, as
its gates now include a refusal audit and verdicts recorded before this
migration are not evidence about the current control. ([#580](https://github.com/Ironsail-llc/genus-os/pull/580))

"All models failed to respond" no longer reaches you while the local fallback
can still answer: each call's context budget now belongs to the model the
engine will actually reach, an overflow is shrunk and re-asked once instead of
being retried five times as a server error, and a run that truly cannot get an
answer says which providers failed, why, and whether the local tier was
reachable. After a top-up or a raised cap, run `genus secrets reload` -- the
new command that makes the running engine re-read its credentials and put
retired keys back in rotation without a restart, which is the only thing that
clears a six-hour quota cooldown early. Run `genus migrate` after deploying
this release, on the instance and on any benchmark pod: migration 124 lets the
new context-overflow control record its own evidence, and until it is applied
those rows are filed as `warned` with one warning in the log. Prove the local
tier before you need it with `genus doctor --only models.local_fallback_ready`;
the credential pool, the reload and the new checks are on the
[Configuration](configuration.md) page. ([#582](https://github.com/Ironsail-llc/genus-os/pull/582))

### For agent authors

When a task names an output path, a header, a field set or section headings,
the engine now reads those as the contract and checks the workspace against
them before a run may call itself done — not just that the file exists — and it
keeps them in front of your agent: compaction may no longer summarise the
statement of the task away (`ROBOTHOR_COMPACTION_PROTECT_FIRST_N`), and the
output contract is re-stated verbatim after every compaction. The progress
check-in now asks your agent to quote the task's required format and show its
file matches it, a tool that times out says what it actually allows instead of
"skip this step", and `exec` output that was cut says how much was cut and what
to do about it. The settings are listed in the
[Configuration reference](reference/configuration.md). ([#580](https://github.com/Ironsail-llc/genus-os/pull/580))

A chain that ends on an `ollama_chat/` model is now sized against that model
once the cloud credentials are spent, so an agent living on the local tier
compacts at its own window rather than the primary's. When the messages still
do not fit, the engine drops the oldest tool results -- keeping the protected
head and the last user turn -- and says so in a `developer` turn, so an agent
that depends on a tool result should re-read it rather than assume it is still
above. Keep a task's requirements in the first few messages, where compaction
protects them; the model chain and its fallbacks are described on the
[Configuration](configuration.md) page. ([#582](https://github.com/Ironsail-llc/genus-os/pull/582))

## 1.95.0 — 2026-09-16

### For operators

An instance with no local GPU can now give its agents vision by setting
`ROBOTHOR_VISION_REMOTE_MODEL` to a provider model, instead of the Ollama model
`ROBOTHOR_VISION_MODEL` names. The model has to be one your engine's registry
declares able to accept images — anything else is refused rather than dialled,
because a provider answers an image sent to an unsupported model with an error
per image. Batch image analysis is bounded by five new settings: how many
images run at once, how long one image gets, how long the whole call gets, how
much of the result comes back inline before the rest is written to a file under
`<workspace>/.robothor/analyze_image/`, and how long the daily sweep keeps
those files. See [Tools](TOOLS.md). ([#581](https://github.com/Ironsail-llc/genus-os/pull/581))

### For agent authors

Agents can now ask one question about up to 200 images in a single
`analyze_image` call. Each image is sent to a vision model on its own and only
the text answers come back, so sorting or labelling a folder of pictures no
longer costs a turn and a context full of image tokens per file — `view_image`
is still the tool for studying one picture yourself. Answers arrive in the
order the paths were given, one image that fails does not cost you the batch,
and anything resolving outside the workspace is refused before a model sees
it. See [Tools](TOOLS.md). ([#581](https://github.com/Ironsail-llc/genus-os/pull/581))

## 1.94.0 — 2026-09-16

### For operators

Events an agent creates for you now land on **your** calendar with an invitation, instead of on the assistant's own Google calendar with you as an attendee and no mail sent — this needs your calendar shared with the instance's account with "Make changes to events", which `genus doctor --category calendar` now checks and names the fix for. `genus doctor` also gains four advisory checks — instructions naming a tool the manifest does not grant, a manifest that denies a Google tool while its `exec_allowlist` admits the CLI doing the same job, an agent that can delete a CRM person, company, note or task with no human in the loop, and whether this engine is actually enforcing the approval gates your manifests declare (see [Tools](TOOLS.md)). The Helm chart now arms that gate at `observe`, which records escalations without blocking anything, and reports the gap as `info` so a correctly-configured instance is not marked degraded for it. Promoting it to `enforce`, which actually denies a delete nobody approved, stays your decision once an approver is wired and soaked — `docs/runbooks/approval-enforce.md` has the steps. ([#579](https://github.com/Ironsail-llc/genus-os/pull/579))

### For agent authors

The Gmail tools return what their descriptions promise: `gws_gmail_search`
gives you sender, subject, date and labels per hit instead of bare ids,
`gws_gmail_get` gives you a decoded `body_text` with attachments listed rather
than inlined, a failed call carries a `hint` instead of a bare exit code, and
every `gws_*` tool is refused on a benchmark run. The calendar tools take a
`calendar` parameter — `operator` (the default) or `own` — because `primary` is
the **assistant's** calendar, and their results carry `calendar`,
`invitations_requested` and `htmlLink` so you can report what actually happened.
`tool_search` now understands the words people use ("check my email", "schedule
a meeting"), answers on a non-deferred run with the agent's own tools instead
of an error, and says outright when a capability does not exist here. The new
[Tools](TOOLS.md) page covers the catalogue, which mail tool is which, whose
calendar is whose, and how deferred loading reaches a tool you cannot see. ([#579](https://github.com/Ironsail-llc/genus-os/pull/579))

## 1.93.0 — 2026-09-16

### For operators

Pictures and files now work both ways over Telegram. Send your assistant a photo, a document, a voice note or a whole album and it keeps the file instead of describing the first frame and forgetting it — the copy lands under `inbox/telegram/<chat>/<date>/` in your workspace, it can open it, and it tells you plainly when the model you are on cannot actually see an image. Ask for a file back and it sends one; a document goes up to 50 MB and a photo up to 10 MB, while anything you send that is over 20 MB is refused by Telegram before it reaches the bot, and the assistant says so rather than going quiet. Kept files are pruned after `ROBOTHOR_INBOX_RETENTION_DAYS` (30 by default), and anything that arrived named or shaped like a credential is quarantined so no tool can read it back out; see [Telegram channel](channels/telegram.md). ([#578](https://github.com/Ironsail-llc/genus-os/pull/578))

### For agent authors

Agents can send a file: the new `send_file` tool takes a path inside the workspace, renders it as a photo or a document, and routes back to the channel the run came from unless you name a target. An inbound turn now carries an `attachments` list alongside the text — path, name, kind, mime, size, image dimensions and the channel ids — so a handler can act on the file rather than on a sentence about it. `view_image` reports `seen_by`, naming the model that actually looked, and refuses instead of silently dropping the image when the active model does not accept one. See [Telegram channel](channels/telegram.md) for the turn shape and the refusals `send_file` can return. ([#578](https://github.com/Ironsail-llc/genus-os/pull/578))

## 1.92.0 — 2026-09-16

### For operators

You can now retire a memory fact, export the audit log as CSV, and read a unit's journal over the API, none of it needing a shell on the box. A forget shows you what it would deactivate before you commit it with a reason, and the audit export admits the read-only `auditor` role, so that job can go to someone who is not given the rest of the instance. See [Deployment](deployment.md) for the routes and what each one is gated on. ([#565](https://github.com/Ironsail-llc/genus-os/pull/565))

You can now switch a plugin off without uninstalling it, and find out which of your plugins stopped loading and why. The verbs are `genus plugin list`, `info`, `enable`, `disable`, `sync` and `doctor`, and a plugin whose files have changed since you recorded it is held back until you look, rather than loaded quietly. A damaged record never stops the instance booting — but nothing is governing while it is damaged, and the doctor and the Helm both say that plainly instead of implying otherwise. See [Plugins](PLUGINS.md). ([#566](https://github.com/Ironsail-llc/genus-os/pull/566))

Observe › Memory, Audit and Logs are screens now rather than placeholders. You can search what this instance believes and retire a fact with a reason, read the guardrail change log, export audit events as CSV with whatever filters you are looking at, and tail a unit's journal. An auditor sees Audit and neither of the other two. See [Deployment](deployment.md) for what each page answers, and for what a forget deliberately does not do. ([#567](https://github.com/Ironsail-llc/genus-os/pull/567))

You can now install a plugin from a signed registry instead of running pip by hand. The index is Ed25519-signed over canonical JSON, the wheel is checked against its sha256 before anything opens it, and an offline scan produces a verdict that gates the install — safe installs, review needs your explicit acceptance, blocked never installs. See [Plugins](PLUGINS.md) for the verdicts and for pinning a publisher's key. ([#569](https://github.com/Ironsail-llc/genus-os/pull/569))

Installing Genus OS is one line: `curl -fsSL https://ironsail-llc.github.io/genus-os/install.sh | bash -s -- --substrate compose`. Every download is pinned to a release tag, the compose files are validated before anything starts, and a piped run without `--yes` is a preview that writes nothing. The Helm chart is published to an OCI registry at each release, so a cluster install no longer needs a clone of the repository. See [Quick Start](quickstart.md). ([#570](https://github.com/Ironsail-llc/genus-os/pull/570))

Hand your assistant a credential over a channel and it can now keep it: the vault is the store for application credentials, so a value the assistant is given is stored, proved against the vendor, and answered for with a fingerprint rather than the secret. `genus secrets status` prints where each credential lives and which store wins, and `genus secrets migrate --from-env` moves the ones still in your secrets file — it refuses bootstrap names, says up front how many vault rows it will not touch, and never replaces a fresher row with a stale environment copy. After the upgrade, restart every Genus process so they all read the same precedence, and delete the migrated entries from the secrets file, because `genus doctor` now reports a dead environment value that was shadowing a live vault row. Your assistant's manifest also needs `v2.credentials: operator` before the vault write tools will answer it; see [Secrets](enterprise/05-secrets.md). ([#576](https://github.com/Ironsail-llc/genus-os/pull/576))

### For admins

Settings › Plugins now lists every distribution the engine loaded, with its version, state, groups and contributions. On a fresh install the first affordance is Record installed plugins, which writes the lockfile; after that an enabled switch and a Reload engine plugins bar apply a change without a restart. A damaged lockfile says plainly that nothing governs instead of implying that something does. See [Plugins](PLUGINS.md) for the same operations from a shell. ([#568](https://github.com/Ironsail-llc/genus-os/pull/568))

The Helm's Plugins page can install from a registry: a name, an optional version, an index picker, and a Preview that shows the artifact, its sha256, the publisher key id and the verdict before anything is installed. Install is enabled only for a safe verdict, or for review once you accept that exact plan, and never for blocked. Remove is offered on the cards the registry installed. See [Plugins](PLUGINS.md). ([#572](https://github.com/Ironsail-llc/genus-os/pull/572))

Microsoft Teams is a channel now, and it ships as the `genus-teams` plugin rather than as part of the core. It delivers over the Bot Framework, asks a question as an Adaptive Card, and validates every inbound request's token before it does anything with it. The channel stays inert until `ROBOTHOR_CHANNELS` names it. See [Teams channel](channels/teams.md) for the Azure app registration and the ingress decision. ([#573](https://github.com/Ironsail-llc/genus-os/pull/573))

### For agent authors

A run now gets pace-aware deadline notes at 50, 80 and 95 per cent of its ceiling, a repeat-call guard that answers an identical read of an unchanged file short, and exec timeouts bounded by the time actually left. All of it sits behind one flag, `ROBOTHOR_STEP_EFFICIENCY_MODE` — off, observe or enforce, observe by default — so it can be watched before it is enforced. See [Configuration](configuration.md) for how to set it. ([#571](https://github.com/Ironsail-llc/genus-os/pull/571))

You can hand an agent to another instance: `genus agent export` writes a bundle with the manifest, the instructions, the referenced skills and a `requires` list, and `genus agent install` takes a path, a directory or a URL with a checksum. A credential literal anywhere in an export is a hard failure, and adapter values are collapsed to environment names before they are written. The Helm offers the same export as a Share button. See [Agents](enterprise/04-agents.md) for the bundle format and what `requires` checks. ([#574](https://github.com/Ironsail-llc/genus-os/pull/574))

An agent that reads the same unchanged file twice now gets a short answer the second time instead of the whole file again. That was the intent before, but the guard resent the file whenever its earlier copy had fallen out of the model's context — which is most of a long run — so an agent could spend a large part of its budget re-reading its own work. A file that really changed is still re-read, so nothing is ever hidden from the model. See [Configuration](configuration.md) for the flag that governs it. ([#575](https://github.com/Ironsail-llc/genus-os/pull/575))

An agent now sees only the credentials its manifest grants it. Name them under `secrets:` and the environment of every process the agent execs is scrubbed to that grant plus a short allowlist, with `ROBOTHOR_EXEC_ENV_MODE` as the ladder from `off` through `observe` to `enforce`; a sub-agent inherits nothing, since its grants are read from its own manifest. `vault_get` no longer hands a value to the model — it answers with a one-way fingerprint, and the new `vault_test` dials the vendor's identity endpoint so an agent can prove a credential works and say who it authenticates as without ever reading it. Read a credential through `robothor.secrets` rather than the process environment, and see [Configuration](configuration.md) for the grant syntax, the ladder and what the scrub leaves behind. ([#576](https://github.com/Ironsail-llc/genus-os/pull/576))
