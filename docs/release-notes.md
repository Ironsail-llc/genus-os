# Release notes

What each release changed, and for whom. Three audiences, because a single
list serves none of them:

- **For operators** — you run an instance: installing, upgrading, backups,
  secrets, the doctor, what a page means at 3am.
- **For admins** — you configure this instance in the Helm: agents, users and
  roles, channels, plugins, flags.
- **For agent authors** — you write manifests, skills and plugins against the
  engine.

A change that is genuinely invisible to all three is recorded in the release
commit and does not appear here.

!!! note "About the first block below"

    This page began with the release that introduced it, and its first version
    block carries entries backfilled from the handful of releases immediately
    before — the work was already shipped; only the note for it is new. Later
    blocks describe exactly the release they name. Delete this note once that
    first block is a few releases old.

This page is written by the release. The developer record — one line per
conventional commit, generated by semantic-release — is `CHANGELOG.md` in the
repository, and it is not going away; it answers a different question.
Contributors: `changelog.d/README.md` is how a pull request adds to this page.

## 1.92.0 — 2026-09-16

### For operators

You can now retire a memory fact, export the audit log as CSV, and read a unit's journal over the API, none of it needing a shell on the box. A forget shows you what it would deactivate before you commit it with a reason, and the audit export admits the read-only `auditor` role, so that job can go to someone who is not given the rest of the instance. See [Deployment](deployment.md) for the routes and what each one is gated on. ([#565](https://github.com/Ironsail-llc/genus-os/pull/565))

You can now switch a plugin off without uninstalling it, and find out which of your plugins stopped loading and why. The verbs are `genus plugin list`, `info`, `enable`, `disable`, `sync` and `doctor`, and a plugin whose files have changed since you recorded it is held back until you look, rather than loaded quietly. A damaged record never stops the instance booting — but nothing is governing while it is damaged, and the doctor and the Helm both say that plainly instead of implying otherwise. See [Plugins](PLUGINS.md). ([#566](https://github.com/Ironsail-llc/genus-os/pull/566))

Observe › Memory, Audit and Logs are screens now rather than placeholders. You can search what this instance believes and retire a fact with a reason, read the guardrail change log, export audit events as CSV with whatever filters you are looking at, and tail a unit's journal. An auditor sees Audit and neither of the other two. See [Deployment](deployment.md) for what each page answers, and for what a forget deliberately does not do. ([#567](https://github.com/Ironsail-llc/genus-os/pull/567))

You can now install a plugin from a signed registry instead of running pip by hand. The index is Ed25519-signed over canonical JSON, the wheel is checked against its sha256 before anything opens it, and an offline scan produces a verdict that gates the install — safe installs, review needs your explicit acceptance, blocked never installs. See [Plugins](PLUGINS.md) for the verdicts and for pinning a publisher's key. ([#569](https://github.com/Ironsail-llc/genus-os/pull/569))

Installing Genus OS is one line: `curl -fsSL https://ironsail-llc.github.io/genus-os/install.sh | bash -s -- --substrate compose`. Every download is pinned to a release tag, the compose files are validated before anything starts, and a piped run without `--yes` is a preview that writes nothing. The Helm chart is published to an OCI registry at each release, so a cluster install no longer needs a clone of the repository. See [Quick Start](quickstart.md). ([#570](https://github.com/Ironsail-llc/genus-os/pull/570))

Hand your assistant a credential over a channel and it can now keep it: the vault is the store for application credentials, so a value the assistant is given is stored, proved against the vendor, and answered for with a fingerprint rather than the secret. `genus secrets status` prints where each credential lives and which store wins, and `genus secrets migrate --from-env` moves the ones still in your secrets file — it refuses bootstrap names, says up front how many vault rows it will not touch, and never replaces a fresher row with a stale environment copy. After the upgrade, restart every Genus process so they all read the same precedence, and delete the migrated entries from the secrets file, because `genus doctor` now reports a dead environment value that was shadowing a live vault row. Your assistant's manifest also needs `v2.credentials: operator` before the vault write tools will answer it; see [Secrets](enterprise/05-secrets.md). ([#576](https://github.com/Ironsail-llc/genus-os/pull/576))

### For admins

Settings › Plugins now lists every distribution the engine loaded, with its version, state, groups and contributions. On a fresh install the first affordance is Record installed plugins, which writes the lockfile; after that an enabled switch and a Reload engine plugins bar apply a change without a restart. A damaged lockfile says plainly that nothing governs instead of implying that something does. See [Plugins](PLUGINS.md) for the same operations from a shell. ([#568](https://github.com/Ironsail-llc/genus-os/pull/568))

The Helm's Plugins page can install from a registry: a name, an optional version, an index picker, and a Preview that shows the artifact, its sha256, the publisher key id and the verdict before anything is installed. Install is enabled only for a safe verdict, or for review once you accept that exact plan, and never for blocked. Remove is offered on the cards the registry installed. See [Plugins](PLUGINS.md). ([#572](https://github.com/Ironsail-llc/genus-os/pull/572))

Microsoft Teams is a channel now, and it ships as the `genus-teams` plugin rather than as part of the core. It delivers over the Bot Framework, asks a question as an Adaptive Card, and validates every inbound request's token before it does anything with it. The channel stays inert until `ROBOTHOR_CHANNELS` names it. See [Teams channel](channels/teams.md) for the Azure app registration and the ingress decision. ([#573](https://github.com/Ironsail-llc/genus-os/pull/573))

### For agent authors

A run now gets pace-aware deadline notes at 50, 80 and 95 per cent of its ceiling, a repeat-call guard that answers an identical read of an unchanged file short, and exec timeouts bounded by the time actually left. All of it sits behind one flag, `ROBOTHOR_STEP_EFFICIENCY_MODE` — off, observe or enforce, observe by default — so it can be watched before it is enforced. See [Configuration](configuration.md) for how to set it. ([#571](https://github.com/Ironsail-llc/genus-os/pull/571))

You can hand an agent to another instance: `genus agent export` writes a bundle with the manifest, the instructions, the referenced skills and a `requires` list, and `genus agent install` takes a path, a directory or a URL with a checksum. A credential literal anywhere in an export is a hard failure, and adapter values are collapsed to environment names before they are written. The Helm offers the same export as a Share button. See [Agents](enterprise/04-agents.md) for the bundle format and what `requires` checks. ([#574](https://github.com/Ironsail-llc/genus-os/pull/574))

An agent that reads the same unchanged file twice now gets a short answer the second time instead of the whole file again. That was the intent before, but the guard resent the file whenever its earlier copy had fallen out of the model's context — which is most of a long run — so an agent could spend a large part of its budget re-reading its own work. A file that really changed is still re-read, so nothing is ever hidden from the model. See [Configuration](configuration.md) for the flag that governs it. ([#575](https://github.com/Ironsail-llc/genus-os/pull/575))

An agent now sees only the credentials its manifest grants it. Name them under `secrets:` and the environment of every process the agent execs is scrubbed to that grant plus a short allowlist, with `ROBOTHOR_EXEC_ENV_MODE` as the ladder from `off` through `observe` to `enforce`; a sub-agent inherits nothing, since its grants are read from its own manifest. `vault_get` no longer hands a value to the model — it answers with a one-way fingerprint, and the new `vault_test` dials the vendor's identity endpoint so an agent can prove a credential works and say who it authenticates as without ever reading it. Read a credential through `robothor.secrets` rather than the process environment, and see [Configuration](configuration.md) for the grant syntax, the ladder and what the scrub leaves behind. ([#576](https://github.com/Ironsail-llc/genus-os/pull/576))
