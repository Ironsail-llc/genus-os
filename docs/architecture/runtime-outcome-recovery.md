# Supported action evidence and recovery

Source audit: product `9163df1d1e6`, 2026-09-21. This inventory describes supported recovery behavior, not certification of every installed business integration. Recorded handler responses, independent readback and completed user objectives are different claims.

| Operation | Durable evidence and recovery | Claim boundary | Executable coverage |
|---|---|---|---|
| Create CRM task | Host reserves an effect UUID before dispatch; trusted dedup code can record the existing task ID. Readback retrieves the tenant-scoped, nondeleted task, including title/body/status. Immediate recovery, authenticated chat polling and terminal sweeps do not repeat the write. | Proves the stored task snapshot. Creating a TODO does not finish that task or its parent goal. A missing/deleted record leaves the outcome unknown; absence alone does not authorize replay. | [Lost commit acknowledgement](../../robothor/engine/tests/test_native_task_uncertainty.py), [deduplicated task recovery](../../robothor/engine/tests/test_native_task_dedup_recovery.py), [browser recovery](../../robothor/engine/tests/test_native_task_browser.py). |
| Create CRM note | Host-reserved effect UUID identifies a tenant-scoped, nondeleted note. Readback recovers its ID/title after a lost acknowledgement. | Proves that stored note, not a downstream message or customer outcome. Missing readback leaves uncertainty. | [Native committed-note response loss](../../robothor/engine/tests/test_native_note_recovery.py), [readback guards](../../robothor/engine/tests/test_note_recovery.py). |
| Add calendar attendees | The calendar operation stores authorized intent and execution evidence. Read-only reconciliation checks the original event; unavailable, empty or wrong-event reads cannot settle it. | Attendees present is distinct from notifications requested. Neither proves invitation delivery. A draft is not an executed change. Recovery never automatically repeats the external update. | [Calendar readback failures](../../robothor/engine/tests/test_calendar_recovery_readback.py), [operation contracts](../../robothor/engine/tests/test_calendar_operations.py), [authenticated chat receipts](../../robothor/engine/tests/test_chat_recovery.py). |
| Pause/cancel/resume a pursuit goal | The same transaction records the control, resulting status/version and trusted originating run/principal in goal history, including affected children. Authenticated run-family recovery reads those immutable records. | Proves that control at that version, not the current state after later steering, completed tasks, or a completed goal. Pause/cancel bookkeeping remains available through its existing admission bypass. | [Native pause followed by model exhaustion](../../robothor/engine/tests/test_native_goal_control_failure.py): parent/child pause, initial/reconnect reply, foreign identity denial, later resume, stale-control rejection and no extra model calls. |
| Other journaled writes with saved successful handler response | The dispatched owner atomically records the returned response as `finished`. A duplicate request can reuse it. | Acknowledgement is not independent verification. Interrupted dispatched effects without a supported verifier remain unresolved; a saved response is not permission for another runtime to repeat a write. | [Effect dispatch](../../robothor/engine/tests/test_effect_dispatch.py), [effect state contracts](../../robothor/engine/tests/test_runtime_effects.py), [receipt presentation](../../robothor/engine/tests/test_chat_effect_receipts.py). |
| Interrupted admission before dispatch | Terminal-owner housekeeping can settle `prepared` as `not_applied`. An abandoned `dispatching` record becomes `uncertain`, with its replay fence retained. | Only a known pre-dispatch boundary proves nonapplication. A dead worker, expired request or failed connection alone does not prove an external write failed. | [Terminal effect recovery](../../robothor/engine/tests/test_effect_recovery.py). |

Initial delivery and reconnect use authenticated tenant/principal/run-family scope. Reading receipts does not upgrade a failed whole request to completed. Later independent evidence can resolve supported effects; it cannot erase other unfinished obligations. Stopped or cancelled runs retain already-dispatched effect records for reconciliation.

## Verification and limits

The [current verification index](../../bench/runtime/uat-verification.json) preserves individual results and earlier failures. The canonical isolated PostgreSQL suite includes actual CRM commit/readback failures, dedup recovery, native chat delivery and goal-control recovery. Calendar tests use a synthetic provider, never historical meetings. The [latest rollback drill](../../bench/runtime/uat-runtime-rollback-goal-history-final-report.json) separately checks saved receipt compatibility across application-code versions.

There is no blanket automatic-readback qualification for arbitrary email, browser, sales or third-party writes. Each additional verifier must prove trusted intent-to-resource binding, tenant/principal isolation, truthful outcome semantics, unavailable/ambiguous-read handling and recovery without redispatch. Human review remains appropriate for judgment-based success criteria; an action receipt alone does not satisfy them.
