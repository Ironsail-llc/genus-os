Coding jobs are refused until you set `ROBOTHOR_CODING_REPO_ROOTS` to the directories repositories may live under (the live workspace and the service user's home are refused even under a root), and every job's shell runs in Claude Code's sandbox, which needs `bwrap` able to create unprivileged user namespaces plus `socat` — `genus doctor` fails `claude_code.ready` without them. Jobs use the engine user's own Claude Code login (the new `zz-claude-code.conf` engine drop-in, installed by `scripts/install-units.sh`, makes `~/.claude` and `~/.claude.json` writable so it can refresh), or a token stored by `genus claude-code login`, and `genus claude-code status` proves either with a one-turn call. Apply migration 144 (`coding_jobs`) before restarting the engine: interrupted jobs resume on the next start, and finished jobs' worktrees, config directories and `genus/cc-*` branches are removed after `ROBOTHOR_CODING_RETENTION_DAYS` (default 7). See [Tools](TOOLS.md) for where worktrees live and what a job may read.
