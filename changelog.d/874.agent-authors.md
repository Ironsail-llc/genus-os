Agents now relay a refusal as the refusal itself states it: one that names its gate is still relayed with the gate and its unlock, and one from another system that names no gate is reported in its own words, with its cause stated as not given and the system's administrator named as who can check. A refusal is never attributed to a switch or mode the agent saw in other tool output, and a message to an end customer carries no error text, tool names, setting names or ids. See [Tools](TOOLS.md#when-a-tool-is-refused).
