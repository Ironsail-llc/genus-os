When a `create_task` call names a `parentTaskId` that no task carries, the call is now
refused as a known error instead of being recorded as an unknown outcome. A bad parent id
therefore settles straight away and no longer fences the tool, so one mistyped id can no
longer block every later write behind an unresolvable outcome. A failure whose outcome
really is unknown still fences exactly as before. See [Tools](TOOLS.md).
