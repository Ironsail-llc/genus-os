One Helm release can now run an engine per child tenant: each entry in the chart's new `tenants:` list gets its own engine, Service and workspace volume, which the bridge and dashboard can reach (see [Deployment](deployment.md) for where the list belongs). Tenants require the new `vaultKey.enabled` and a `vault-key` Vault path holding a base64 `key` and `fingerprint-salt`, so the bridge and every engine share one vault key; on a release that already has a `.vault-key`, copy that key and its `.fingerprint-salt` into Vault rather than generating new ones, because a new key makes every stored secret unreadable ([the chart README](https://github.com/Ironsail-llc/genus-os/blob/main/helm/genus-os/README.md#tenant-cells) shows how). The root engine now sets both tenant variables from the new `global.rootTenant`, whose default of `default` changes nothing. If your `engine.env` sets `ROBOTHOR_TENANT_ID` or `ROBOTHOR_DEFAULT_TENANT` to anything else, move that value to `global.rootTenant`, or the chart will refuse to render.
