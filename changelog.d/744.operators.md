One Helm release can now run an engine per child tenant: each entry in the chart's new `tenants:` list gets its own engine, Service and workspace volume, which the bridge and dashboard can reach. Tenants require the new `vaultKey.enabled` and a `vault-key` Vault path holding a base64 `key` and `fingerprint-salt`, so the bridge and every engine share one vault key and a credential stored for a child can be read by that child's engine. The root engine now sets both tenant variables from the new `global.rootTenant` (default `default`, which changes nothing); if your `engine.env` sets `ROBOTHOR_TENANT_ID` or `ROBOTHOR_DEFAULT_TENANT` to anything else, move that value to `global.rootTenant`, or the chart will refuse to render. See [Deployment](deployment.md) for where the tenant list belongs.
