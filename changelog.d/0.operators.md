You can now see what a change to memory recall would do before it goes live: `genus memory-replay --tenant <tenant>` replays the tenant's past `search_memory` queries (`--from-runs`), recent chat questions (`--from-chat`) or a file of questions through today's recall and the new recall side by side, and reports per question what each returned, the overlap, the rows only one side found, latency and context size. It is read-only, with every database connection it opens refusing writes, and each question is read as the person it belongs to. The report contains tenant memory; `--redact` replaces the text with ids and lengths. See [Memory System](memory-system.md#replaying-real-questions-before-a-change-goes-live).
