Personal automation is now off unless you turn it on, and turning it off stops a task being finished as well as being started: reconciling an uncertain result, arming an external-verification check and recovering one after a restart all re-read your switch and your grant first. Until you set `ROBOTHOR_AUTONOMY_ENABLED=true` there is no Personal automation page, no autonomy paragraph on any agent's prompt and no autonomy wording in the browser tool, so an instance that never enrols anything pays nothing for the feature. A verification that lapses no longer leaves its budget stuck — the task moves to "waiting for you" and you can clear it from the Personal automation page. See [Autonomous execution](AUTONOMOUS_EXECUTION.md) for the states and what each refusal means.

Telegram: a photo album no longer loses members. One picture that failed to download used to end the batch silently — a four-photo album arrived as one photo with no reply at all — and each member now reports its own failure and the rest still arrive. A batch bigger than I can take at once keeps the first 25 and tells you how many were left over, instead of refusing all of them as "private". `/secure` no longer replies to someone this instance has never heard of: a stranger used to be told where the dashboard is and you were never told they had written, and now they get the ordinary refusal and you get the alert, with nothing from their message quoted back to you. In a group chat `/secure` is refused without reciting the dashboard path to the room. A message whose second line happens to start with `/secure` still has that line and everything after it withheld, but now says so instead of quietly arriving short.

A submission record can be erased. **Erase submission record** under a task on the Personal automation page removes the page text the browser observed — your name, date of birth, address and the answers you gave a website — and keeps only the fact that a record was taken, when, and under which grant. Records also expire on their own after a year (`ROBOTHOR_AUTONOMY_TERMS_RETENTION_DAYS`, 0 to keep them forever). Payment events are kept for seven years and are not swept automatically, because a payment's position is reconstructed from its whole event log.

Contract documents are now read only from the websites your grant lists, from its payment-provider frames, or from the website the task is on — "allow any public HTTPS website" is permission to visit a site you chose, not permission for that site's markup to point at somebody else's. An oversized document is refused before it is downloaded rather than after. A shared mail provider (gmail.com, outlook.com, sendgrid.net, amazonses.com and the like) can no longer be authorised as a website's verification sender: authorising one would make every account at that provider proof of verification for that website, and the sender domain has to belong to the website alone. Where more than one verification message matches, the oldest wins.

When a verification code or TOTP means the page cannot be observed before a click, that refusal is now itself recorded, so an empty audit trail no longer looks the same as the feature being switched off. A receipt another agent is not allowed to read reports a denial instead of looking like a flaky page.

Upgrade note: a grant that names a shared mail provider as a verification sender stops working until you remove it, and this release's grants cannot be read by the previous one if they use purposes or verification senders. Apply migrations 142 and 143.
