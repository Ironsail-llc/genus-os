A root-tenant owner or admin can now switch into a descendant tenant and act there, through `POST /api/auth/switch-tenant`; the acting tenant is carried in the access token, never in a header, and a child tenant's admin can reach neither its parent nor a sibling. It is off until you set `GENUS_TENANT_SWITCH_MODE` (`observe` logs what it would do, `enforce` issues tokens), and `enforce` refuses unless row-level security is genuinely enforcing — the same check federation uses. With RLS on, the bridge now binds every signed-in request to its token's tenant, and sign-ins find accounts in any tenant. See [Configuration](configuration.md) for the routes and [Settings](reference/configuration.md) for the two new settings.
