The daily guardrail check no longer reports two findings an instance cannot
fix. `ROBOTHOR_CALENDAR_SEND_UPDATES` names an audience (`all`, `externalOnly`,
`none`) rather than a rollout rung, so the flag inventory can now declare that
and the audit reads a correctly-defaulted setting as correct instead of
flagging it every morning; the same audit also stops reporting an ungated flag
as `observe` when the engine actually runs its own default, and stops claiming
the `ROBOTHOR_DISABLE_ALL_RIPS` switch turns off the two controls it was never
wired to. `ROBOTHOR_PER_USER_SESSIONS` and `ROBOTHOR_DNC_MODE` now ship set in
the engine's systemd drop-in, so the posture an upgrade restores is the one
recorded rather than whatever an unversioned environment file happened to
carry — if you set either in `/etc/robothor/robothor.env`, delete that line
when you upgrade, since the environment file is applied last and keeps
winning. See [Configuration reference](reference/configuration.md) for both
settings.
