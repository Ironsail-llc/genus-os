Memory reached through `deep_reason`, the `robothor-memory` MCP server or the orchestrator's `/ingest`, `/stats`, `/query` and `/v1/chat/completions` endpoints is now read and written as the caller's tenant, where before it always went to the default tenant. On a deployment with more than one active tenant, a call that names no tenant is now refused (the orchestrator answers 400), so a script that posts to the orchestrator should send `X-Tenant-Id`; a single-tenant install behaves as before. See [Tools](TOOLS.md#whose-memory-every-entry-point-acts-as-the-callers-tenant) for where each entry point takes its tenant from.
