The weekly Postgres base backup no longer refuses to run on a volume whose mount root is owned by root: the script probes the directory it actually writes under, the same one the unit's start condition checks. If your instance's `robothor-basebackup` unit has been failing with "not a usable backup volume", it will work from the next scheduled run; run it once by hand to restore a fresh PITR base. See [Backup and upgrade](enterprise/06-backup-upgrade.md).
