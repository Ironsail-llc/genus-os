A hook-triggered workflow no longer loses events in a burst. Every event it takes is written to the workflow's backlog in Redis before it is acknowledged, then runs once, in arrival order, at the workflow's `rate_limit_per_minute`, and the backlog survives a restart. A `requeue_if_busy` event now waits as long as the workflow is busy instead of about 50 minutes before the dead-letter stream, and a burst of N single-call events takes about N ÷ limit minutes. See [Event bus](event-bus.md).
