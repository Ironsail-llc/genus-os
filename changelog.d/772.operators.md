On Kubernetes, the dashboard's Providers, Channels and Plugins pages no longer
report the engine as unavailable: the chart now points the bridge at the engine
Service through `ROBOTHOR_ENGINE_URL` and its network policy lets the bridge
reach the engine. See [Configuration](reference/configuration.md).

The bridge's `/ready` now says whether it can reach the engine. An unreachable
engine keeps the answer at 200 but adds `degraded: true` and an `engine` field
naming the failure, and the doctor's Health view lists a `bridge.engine` row
with the address it tried. Alert on `degraded`; see
[Deployment](deployment.md#from-the-dashboard).

Save default on the Providers page, and the setup wizard's default-model step,
now work when the bridge and the engine run in separate containers: the engine
writes the fleet default model block to `_defaults.yaml` in its own manifest
directory and reloads it before it answers, so the bridge no longer needs the
workspace volume, and a successful save always means the fleet is running on
the new model. See [Deployment](deployment.md#model-providers).

When the bridge cannot reach the engine, Settings › Providers says so in terms
you can act on: it names `ROBOTHOR_ENGINE_URL` and asks you to check that the
engine is running and that the network path from the bridge to the engine is
allowed. If only the current fleet default could not be read, you can still
choose a primary model and save it, and Save says why it is disabled when there
is nothing to choose. Try again re-reads the providers, the model catalog and
the fleet default together.

On Kubernetes the dashboard's live event views now work: the chart gives the
dashboard the in-chart cache's host, port and password key, lets it through the
NetworkPolicy, and restarts it when the cache password rotates, which ends the
once-a-second cache connection error in its logs. The dashboard reads only the
cache password key, never the whole cache Secret. See [Event bus](event-bus.md)
for how it picks its connection.
