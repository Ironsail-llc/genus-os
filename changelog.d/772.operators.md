On Kubernetes the bridge now reaches the engine (the chart sets
`ROBOTHOR_ENGINE_URL` on the bridge and opens the network policy both ways), so
Settings › Providers lists providers, models and the fleet default again, and
when the engine is unreachable the page names what to check instead of
"engine unavailable". The bridge's `/ready` stays at 200 but adds
`degraded: true` and an `engine` field when the engine cannot be reached, and
the doctor lists a `bridge.engine` row with the address it tried. Save default
and the setup wizard's default-model step now work with the bridge and the
engine in separate containers, because the engine writes `_defaults.yaml` in
its own manifest directory and reloads it before answering. The dashboard's
live event views work on Kubernetes too, because the chart gives the dashboard
the in-chart cache's host, port and password key, lets it through the policy
and restarts it on rotation, which ends the once-a-second cache error in its
logs; see [Configuration](reference/configuration.md),
[Deployment](deployment.md) and [Event bus](event-bus.md).
