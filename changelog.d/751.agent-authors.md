A plugin's own rule can now decide the plugin's proposals. `Operations.decide` accepts `policy:<plugin>:<version>` for actions proposed with `proposed_by="<plugin>"`, and the audit trail records which version of the rule acted. Every approval publishes `operation_action.approved` on the `operations` stream, so a workflow your plugin ships can execute the action as soon as it is approved. New store methods (`list_actions`, `claim_action_by_id`, `cancel_action`, and a full-row `get_action`) mean a plugin never has to query the ledger tables itself. See [Plugins](PLUGINS.md#proposing-an-external-effect) and [Operations ledger](OPERATIONS.md).
