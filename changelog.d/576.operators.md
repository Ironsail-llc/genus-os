Hand your assistant a credential over a channel and it can now keep it: the vault is the store for application credentials, so a value the assistant is given is stored, proved against the vendor, and answered for with a fingerprint rather than the secret. `genus secrets status` prints where each credential lives and which store wins, and `genus secrets migrate --from-env` moves the ones still in your secrets file — it refuses bootstrap names, says up front how many vault rows it will not touch, and never replaces a fresher row with a stale environment copy. After the upgrade, restart every Genus process so they all read the same precedence, and delete the migrated entries from the secrets file, because `genus doctor` now reports a dead environment value that was shadowing a live vault row. Your assistant's manifest also needs `v2.credentials: operator` before the vault write tools will answer it; see [Secrets](enterprise/05-secrets.md).
