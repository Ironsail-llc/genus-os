An engine restart no longer pages you for stopping: since the previous release
the engine's own health server re-raised the one SIGTERM systemd had sent, the
engine read that as a second signal and exited 1, and every deploy looked like
a failure to `OnFailure=`. A repeat of the stop signal inside two seconds of
the first is now recognised as the same stop and ignored, and the health
server no longer touches the process's signal handlers. A deliberate second
`kill` later in a hung drain still ends the engine at once but exits 0 — a stop
you asked for is not a crash — while a drain that outlives `TimeoutStopSec` is
still killed by systemd and still pages. See
[Backup, restore and upgrade](enterprise/06-backup-upgrade.md) for the upgrade
path this makes quiet again.
