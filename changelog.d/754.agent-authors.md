A plugin channel can now serve many conversations at once: messages in one
conversation run in order, different conversations run side by side, and every
successful exchange is remembered in the conversation's history, across
restarts. `handle_message` takes `record_turn` and `history_limit` to opt out of
that memory or bound it, and `ROBOTHOR_CHANNEL_MAX_CONCURRENT_RUNS` (default 8)
caps the runs all channels have in flight, queueing rather than refusing. See
[Plugins](PLUGINS.md) and [Configuration](configuration.md).

The engine no longer asks for its own token on a `POST` to a mounted channel's
path, so every `POST` route in a channel's `inbound_router` must authenticate
the request itself and refuse it with its own `401` or `403`.
