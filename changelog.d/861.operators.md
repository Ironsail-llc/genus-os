Child tenants that run an agent with the same id as another tenant now get their own schedule row. The `agent_schedules` key is `(tenant_id, agent_id)`, so the `Failed to upsert schedule` row-level security warning stops, those jobs appear on the tenant's fleet and automations views, and their circuit breaker and catch-up start working, which means a job failing repeatedly in that tenant will now pause. `genus tenant move-workload` also carries an agent's heartbeat, worker and ambient schedule rows, and refuses a job the target already holds. An older release still starts beside this key, but logs a warning for each schedule write until you roll forward; see [rolling back](deployment.md#rolling-back-to-an-older-release).
