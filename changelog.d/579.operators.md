Events an agent creates for you now land on **your** calendar with an invitation, instead of on the assistant's own Google calendar with you as an attendee and no mail sent — this needs your calendar shared with the instance's account with "Make changes to events", which `genus doctor --category calendar` now checks and names the fix for. `genus doctor` also gains four advisory checks — instructions naming a tool the manifest does not grant, a manifest that denies a Google tool while its `exec_allowlist` admits the CLI doing the same job, an agent that can delete a CRM person, company, note or task with no human in the loop, and whether this engine is actually enforcing the approval gates your manifests declare (see [Tools](TOOLS.md)). The Helm chart now arms that gate at `observe`, which records escalations without blocking anything, and reports the gap as `info` so a correctly-configured instance is not marked degraded for it. Promoting it to `enforce`, which actually denies a delete nobody approved, stays your decision once an approver is wired and soaked — `docs/runbooks/approval-enforce.md` has the steps.
