Events an agent creates for you now land on **your** calendar, with an
invitation: they were going to the assistant's own calendar — `primary` is the
assistant's Google account, not yours — with you as an attendee and no mail
sent, so nothing ever reached you. This needs your calendar shared with the
instance's Google account with "Make changes to events", which
`genus doctor --category calendar` now checks and names the fix for. `genus
doctor` also gains three advisory checks: for agents whose instructions name a
tool their manifest does not grant, for a manifest that denies a Google tool
while its `exec_allowlist` admits the CLI doing the same job, and for an agent
allowed to delete or send something without a human in the loop. That last one
reads the engine's own settings, because the approval gate needs two
environment variables and setting only the obvious one leaves it off — both are
now set by the Helm chart, which previously set neither. See
[Tools](TOOLS.md).
