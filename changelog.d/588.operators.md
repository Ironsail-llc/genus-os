An instance with no local GPU can now use `view_image`. Previously only
`analyze_image` fell back to `ROBOTHOR_VISION_REMOTE_MODEL`, so agents in a
container were told there was no vision at all and went on to answer from
filenames instead. A call that still cannot be answered now names each rung it
tried, so a misconfigured remote model reads differently from an absent one —
and note that a remote fallback is billed per call, so leave the setting unset
where a local vision model works. See
[Tools](TOOLS.md#vision-view_image-and-analyze_image).
