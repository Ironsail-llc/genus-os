`ROBOTHOR_DELIVERABLE_CONTRACT_MODE` changes what `enforce` does: it used to
record a verdict, and it now re-asks the agent once with the report and then
fails a run whose deliverable is the wrong shape rather than letting it report
`completed`. The default is unchanged (`observe`, and the master switch off),
and a new migration adds `agent_runs.task_text` — the originating prompt,
redacted and capped — because the check had no source of task text before it.
Both settings are listed in the
[Configuration reference](reference/configuration.md); read the
deliverable-contract runbook in the repository before promoting the rung, as
its gates now include a refusal audit and verdicts recorded before this
migration are not evidence about the current control.
