Code that `deep_reason`'s inner model writes can no longer import the platform's own modules or the database and Redis drivers, and the whole session now runs bound to the run's tenant. Before, that code could import the memory layer and read another tenant's rows directly. This is a guard, not a sandbox: on a multi-tenant deployment, keep row-level security on with the non-superuser role, and don't grant `deep_reason` to an agent whose prompts an untrusted party controls. See [Tools](TOOLS.md#whose-memory-every-entry-point-acts-as-the-callers-tenant).
