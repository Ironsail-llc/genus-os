Memory recall now returns as much relevant memory as its 4,000-character context cap allows: the reranked head first, then the remaining candidates in fused order, leaving out rows about a different person or company who shares a name with one the question names. On the memory eval this raised answer accuracy from about 49% to 63-66% with a 32b answer model and from about 51% to 62-67% with the local 8B one, on both the dev and held-out splits; with the 8B model the dev split's cross-tenant name stratum still regresses. The reranker still scores only its 16 rows, MCP `search_memory` follows the same rule, and every returned row keeps the same tenant, scope and private-reader rules.
