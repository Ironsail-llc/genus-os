Confirmed meeting attendee drafts can execute without another model call, preserve existing guests and RSVPs, and stop after one verification. A confirmation binds only to the confirming user's own still-open draft, is used once, and is skipped in plan mode, so a bare "yes" can never replay a finished operation. Every calendar result names the calendar it applied to, reports a declined RSVP as declined, and says whether the event recurs. An interrupted write that provably never reached the calendar clears its own barrier instead of freezing the meeting. The opt-in operation records durable state to prevent duplicate writes; interactive runs now report progress and avoid repeated ineffective context compaction. `ROBOTHOR_CALENDAR_OPERATIONS_ENABLED` requires an engine restart. See [Interactive request performance](runbooks/INTERACTIVE_REQUEST_PERFORMANCE.md) for rollout, measured results, and how to clear a reconciliation barrier.
