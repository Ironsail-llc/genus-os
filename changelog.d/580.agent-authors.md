When a task names an output path, a header, a field set or section headings,
the engine now reads those as the contract and checks the workspace against
them before a run may call itself done — not just that the file exists. Three
benchmark tasks scored zero with the file present and the columns renamed, so
the deliverable contract grew typed items (exact output set, header, JSON
fields, headings, sort order), each read only from explicit spec language and
each quoting the sentence it came from. A run's originating prompt is now
persisted on `agent_runs.task_text`, redacted and capped, which is what gives
the check a source at all. The two settings that govern it are in the
[Configuration reference](reference/configuration.md); the deliverable-contract
runbook in the repository says what is extracted and what is checked.
