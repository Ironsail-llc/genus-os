A root admin who switches into a child tenant, and that tenant's own admins, can now run the tenant from the Helm: its agents, automations, runs, approvals, channel pairings, memory, accounts, provider keys, plugins and audit log, with each page talking to that tenant's own engine. On Settings › Plugins a child's admins enable and disable their tenant's plugins, a plugin the root tenant has forced on or off shows a locked switch set by the root, and a root admin at home sets those choices for each child; installing plugins and the appliance-wide pages (Controls, Settings, Logs, the doctor and marketplace installs) stay with a root admin at home. The audit log records each event's tenant, sign-ins included, so an audit export holds only the tenants you may see; see [Deployment](deployment.md#acting-in-another-tenant-from-the-helm) and [Plugins](PLUGINS.md#per-tenant).
