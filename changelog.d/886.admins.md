In a tenant hierarchy, the parent's agent now knows the organisation it serves and can see and act in the child tenants: a parent's owner or admin can ask how every company is doing, drill into one, and have it create or update work there, previewing any change with a dry run. Only a top-level run by a parent's owner or admin reaches a child, every such call is audited, and a scheduled agent reaches the children only when the parent's `child_data_access` is set and its manifest opts in. An owner or admin who switches into a child tenant keeps their name and role in the conversation, and the operator-facing agent starts a conversation knowing the fleet roster.
