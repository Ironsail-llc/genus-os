A new setting, `ROBOTHOR_DB_FAST_CHECKOUT`, makes database access cheaper. It
is off by default. When on, a connection is checked out without starting a
thread, the tenant binding and vector-scan setting are sent only when they
change, and the hottest read helpers run without a transaction, so a repeat
single-statement read costs one round trip instead of five. Leave it off behind
a transaction-mode connection pooler. See [Configuration](reference/configuration.md).
