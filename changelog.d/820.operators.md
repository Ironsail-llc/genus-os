A new setting, `ROBOTHOR_DB_FAST_CHECKOUT` (off by default), makes database
access cheaper: connections are checked out without starting a thread, and the
tenant binding and vector-scan setting are sent only when they change. The
hottest read helpers then run without a transaction, so a repeat
single-statement read costs one round trip instead of five. Leave it off behind
a transaction-mode connection pooler; see [Configuration](reference/configuration.md).
