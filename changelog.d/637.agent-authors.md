An agent can now hand a coding task to Claude Code and get back a verified commit instead of a claim: `claude_code_start` runs the task in its own git worktree, and the engine runs your acceptance command itself, checks for a commit on the job's branch, and resumes the same Claude Code session with the failure until it passes or the round and budget limits run out. The tools are opt-in (`tools_allowed`, or the new additive `tools_opt_in` manifest key), and the `claude-code` skill describes how an orchestrator should use them. Every job runs fenced — a sandboxed shell with no credentials and no network by default, edits confined to the worktree, `review`/`readonly` jobs that write nothing and take no `verify_command` — and only the agent that started a job, or the owner, can see or steer it. See [Tools](TOOLS.md) for modes, limits, evidence and the security model.
