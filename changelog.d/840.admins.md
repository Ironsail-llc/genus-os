An owner or admin can now hand the default chat agent an API key in chat and have it stored, tested and answered for with a fingerprint, when `ROBOTHOR_CREDENTIAL_INTAKE` is set to `enforce` (default `off`; `observe` logs what would be allowed). Members, sub-agents and scheduled runs are still refused, and the refusal says which gate held and what opens it. Settings › Secrets can now remove a credential from the vault. See [Configuration](configuration.md).
