Finishing a run no longer holds up the engine while it publishes telemetry: the
Redis entry and the OTLP trace export run in the background on shared clients,
so a slow or unreachable collector cannot stall other chats and runs. Every run
now exports its trace, whatever the outcome, under one `agent_run` root span
that covers the whole run and carries an error status and the reason when it
did not finish cleanly. Spans carry an OpenTelemetry span kind, and the trace
resource takes the standard `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_NAME`
settings; see [Observability](OBSERVABILITY.md).
