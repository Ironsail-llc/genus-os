An agent that reaches its tools through `tool_call` no longer gives up on all of them after three unrelated failures: a wrapped call's failure counts against the tool it wraps, so the circuit breaker, `agent_tool_events`, the per-kind error hints and the no-progress detector name the real tool. Inside `execute_code` a `tool_call` is judged as the tool it wraps too, so the snippet denylist refuses `tool_call(name="spawn_agent")` like `spawn_agent` itself and a wrapped approval-gated tool counts toward the one-approval cap. See [Tools](TOOLS.md#deferred-loading).
