An agent with more than 40 tools is now shown its core tools (the platform's
fixed set plus the tools it called in its last 10 runs) and finds the rest with
`tool_search`, so the main agent's tool block drops from about 32,000 to about
6,600 estimated tokens per request on a stock install.
`ROBOTHOR_DEFERRED_TOOLS_THRESHOLD` sets the tool count,
`ROBOTHOR_DEFERRED_TOOLS_RECENT_RUNS` how many runs seed the core, and a
manifest's `tools_eager` list names tools always in it (the `main` template
makes its task and mail reads eager), while `tool_search` returns its top hit's
parameters when it clearly leads the next, so the usual path needs no
`tool_describe`. A search's top three hits also join the run's toolset with
their own schemas from the next model call on, so the model calls them
directly rather than through `tool_call`. `tool_search` and `tool_describe` are
read-only: they make no effect reservation and are offered in plan mode.
The new `tools.deferred_tools_reachable` doctor check reports a granted tool an
agent could not reach. See [Tools](TOOLS.md#deferred-loading).
