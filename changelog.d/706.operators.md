Staging and production can now trust a managed database's private CA: put the
PEM bundle in a ConfigMap and name it in `database.tls.caConfigMap`, and the
services and migration Job verify the server against it, as described in
[Trusting the database's CA](deployment.md#trusting-the-databases-ca).
In any environment the chart now refuses to render `verify-ca` or
`verify-full` without that bundle, unless `database.tls.allowDefaultTrustStore`
says the pods' default `root.crt` is intended. The migration Job is renamed
whenever its pod template changes, so such changes no longer fail on an
immutable Job, and the dashboard's readiness probe now waits long enough for
its backend checks.
