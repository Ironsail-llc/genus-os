The cache and event bus the chart ships is now Valkey instead of the groundhog2k
Redis StatefulSet; `redis.enabled`, `redis.host` and `redis.port` keep working,
but the old `redis.*` server overrides now do nothing and must move under
`valkey.*`. On `helm upgrade` an instance running the bundled Redis starts on a
new, empty `{release}-valkey` volume, so the bus's consumer-group offsets,
pending entries and dead-letter queue are not carried over — let the bus drain
and acknowledge everything before upgrading. `global.imagePullSecrets` is now a
list of secret names rather than `{name: ...}` entries, and a values file still
using the old map form stops images pulling on every first-party pod. See
[Upgrading the cache to Valkey](deployment.md#upgrading-the-cache-to-valkey) for
the full sequence, including deleting the old claim.
