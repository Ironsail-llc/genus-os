The cache and event bus the chart ships is now Valkey instead of the groundhog2k
Redis StatefulSet; `redis.enabled`, `redis.host` and `redis.port` keep working,
but `redis.image`, `redis.storage`, `redis.resources` and the other old subchart
overrides now do nothing and must move under `valkey.*`. On `helm upgrade`, an
instance running the bundled Redis starts on a new, empty `{release}-valkey`
volume, so the bus's consumer-group offsets, pending entries and dead-letter
queue are not carried over: let the bus drain and acknowledge everything before
upgrading. The old `{release}-redis` claim is left in place, not migrated;
delete it once the new cache is healthy. See
[Upgrading the cache to Valkey](deployment.md#upgrading-the-cache-to-valkey).
