A plugin can now ship agents, workflows, edits to an existing agent and other
workspace files: declare them under `agents`, `workflows`, `patches` and
`files` in `genus-plugin.yaml`. `genus plugin install` and `genus plugin sync`
render and copy them, keeping the operator's agent overrides across upgrades,
and `genus plugin remove` retires them. See
[Plugins](PLUGINS.md#shipping-agents-workflows-and-workspace-files).

`genus plugin new <name>` scaffolds a plugin repository that builds a correct
wheel as-is: an example tool and its schema, an agent template, the
`genus-plugin.yaml` declaring both, contract tests, and a CI workflow that
builds the wheel and prints its sha256. See
[Plugins](PLUGINS.md#starting-a-plugin).
