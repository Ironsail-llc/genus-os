The pull-request reviewer now runs three reviews at once and no longer drops a re-review request: reposting a pull request's links counts as a request, and a reply it cannot read gets a "Want a re-review?" question in its thread. The `pr-review-run` workflow now runs the `pr_review_work` tool instead of waking the reviewer agent, so copy the updated template, set `ROBOTHOR_CODING_MAX_CONCURRENT` to at least `ROBOTHOR_PR_REVIEW_WORKERS` and apply migrations 150 and 151. Main can report on reviews with `pr_review_status`. See [the PR reviewer guide](PR_REVIEWER.md#monitoring).
