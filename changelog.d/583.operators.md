`ROBOTHOR_PARALLEL_TOOL_CALLS` (default 4) decides how many of one turn's tool
calls run at once; only calls the platform has classified read-only are ever
grouped, and 1 restores the previous strictly sequential behaviour. The new
`execute_code` tool lets a granted agent run Python that calls its own tools,
bounded by `ROBOTHOR_EXECUTE_CODE_MAX_CALLS`, `ROBOTHOR_EXECUTE_CODE_TIMEOUT`,
`ROBOTHOR_EXECUTE_CODE_MAX_OUTPUT` and `ROBOTHOR_EXECUTE_CODE_MAX_APPROVALS`; it
requires `exec`, refuses a container-sandboxed agent, and always runs with the
scrubbed child environment whatever `ROBOTHOR_EXEC_ENV_MODE` is set to. All five
settings are listed in the
[Configuration reference](reference/configuration.md). **Run `genus migrate`
before restarting the engine on this release**: a new migration adds
`agent_run_steps.batch_id` / `batch_position`, and until it is applied the step
writer records the older shape and says so once at ERROR.
