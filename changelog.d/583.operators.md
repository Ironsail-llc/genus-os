`ROBOTHOR_PARALLEL_TOOL_CALLS` (default 4) decides how many of one turn's tool
calls run at once; only calls the platform has classified read-only are ever
grouped, and 1 restores the previous strictly sequential behaviour. The new
`execute_code` tool lets a granted agent run Python that calls its own tools,
bounded by `ROBOTHOR_EXECUTE_CODE_MAX_CALLS`, `ROBOTHOR_EXECUTE_CODE_TIMEOUT`
and `ROBOTHOR_EXECUTE_CODE_MAX_OUTPUT`; it requires `exec`, refuses a
container-sandboxed agent, and always runs with the scrubbed child environment
whatever `ROBOTHOR_EXEC_ENV_MODE` is set to. All four settings are listed in the
[Configuration reference](reference/configuration.md), and a new migration adds
`agent_run_steps.batch_id` / `batch_position` so the step trail records which
calls ran together.
