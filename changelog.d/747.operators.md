Several engines, one per tenant, can now share one Redis: give each child engine its own consumer group with `GENUS_EVENT_CONSUMER_GROUP` (for example `engine-<tenant>`), while the root engine keeps the default `engine` and the stream positions it already holds. Every published event now names its tenant and an engine acts only on its own tenant's events, with untagged events still going to the root engine. A child engine left on the root's group logs an error and does not read events until you set its group. See [Event Bus](event-bus.md#one-engine-per-tenant).
