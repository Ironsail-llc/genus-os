When the local embedding server answers with an empty or wrong-width vector, as it can under load, the memory system now catches it at the embedder instead of failing deep in SQL with a pgvector "different vector dimensions" error. The vector is retried once, then the error names the embedding model and the width it got against the 1024 it expects. Memory and knowledge-base search fall back to keyword-only results, as they do when the embedding service is down. See [Memory system](memory-system.md).
