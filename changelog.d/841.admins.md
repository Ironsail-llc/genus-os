A missing container runtime no longer fails runs that asked for a sandbox: the `exec` of an owner or admin driving the run runs on the engine host with a note, and anyone else, including cron, repair-resumed and sub-agent runs, is refused per call with the gate and the unlock named. That owner or admin is also not bound by the exec allowlist and may run `execute_code` beside a live container, each recorded. Every `exec` and `execute_code` result says where it ran, and `genus doctor --category sandbox` shows, per agent, where an owner's and a member's commands would go. See [Tools](TOOLS.md) for the result fields.
