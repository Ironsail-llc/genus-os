A new flag, `ROBOTHOR_SANDBOX_PLAYGROUND` (off by default), stops a missing container runtime from failing runs that asked for a sandbox: the `exec` of an owner or admin driving the run runs on the engine host with a note, and anyone else, including cron and other automated runs, is told which gate stopped them and how to unlock it. That owner or admin is also not bound by the exec allowlist and may run `execute_code` beside a live container, each recorded; every `exec` and `execute_code` result says where it ran. `genus doctor --category sandbox` shows, per agent, where an owner's and a member's commands would go. See [Tools](TOOLS.md) for the result fields.
